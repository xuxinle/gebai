### 2.1 安全与权限模型（先定边界，再谈功能）

- **根（root）是权限边界**：`resolveRoot()` 把 `sess:<id>` / `proj:<name>` / `bind:<agent>` / `user:` / `abs:<path>` 解析为绝对路径；`abs:` 在服务模式（沙箱）下一律拒绝，只允许注册的项目根与用户目录。
- **两条写开关**：`GEBAI_FS_WRITE=false` 全局只读；git 另有 `GEBAI_GIT_WRITE` / `GEBAI_GIT_REMOTE`（远程操作单独放行）。

### 5.1 消息流 → 工作台（第二轮补入）

入口不止标题栏那一个：**消息流里的文件产物本身就是入口**。

| 位置 | 按钮 | 说明 |
|---|---|---|
| 文件链接 chip（弹窗查看模式） | 「在文件工作台中打开」+ 下载 | chip 本体仍点开预览弹窗，两个图标按钮 `stopPropagation` 不触发它 |
| 文件卡工具栏（嵌入模式，`code`/`file` 块） | 「在文件工作台中打开」+ 复制 + 原文件 | hover 渐显的工具栏内 |
| 原文件弹窗标题栏 | 「在文件工作台中打开」+ 下载 + 全宽 | 预览后想直接改：一键抳进 IDE |

- **会话归属不漂移**：chip 显式携带**渲染时**的会话 id（`opts.session`），历史消息里的产物不会因当前会话切换而开错工作区。
- **主界面不解析根**：只把原始路径透传（`/files?session=…&path=…`），由工作台 `files/deeplink.ts` 定位所属根。原因：产物路径有两类（会话相对 `tmp/` 逻辑路径 / 项目绝对路径），主界面若自行匹配根，就要复制一份根清单与匹配规则，根的增删/改名都会让它失配。
- **定位规则（三档优先级）**：① 显式 `?root=`/`?project=`；② 绝对路径 → **最长前缀匹配**的根（平局时按类型：proj/bind > sess > user > abs，因为本地模式的 `abs:` 白名单根常与注册项目指向同一目录，不应抢占项目根）；③ 其余 → `?session=` 的会话根（无参数默认项目根 → 绑定根 → 第一个根）。`?line=` 打开后跳行；`tmp/` 前缀自动剥离。
- **可测性**：解析逻辑抽为独立纯函数模块（参数可注入 `search`/`isWin`、无 DOM 依赖）——`main.ts` 顶层会建 DOM 与启动，无法直接对其单测；抽离后得 23 例单测（显式根 / 嵌套根取最精确 / Windows 盘符大小写 / temp 前缀 / 中文空格路径 / 无匹配回退）。
- **实测（Playwright，真实服务）**：

```
① 绝对路径 /workspaces/gebai/packages/server/src/app.ts → 打开 app.ts（41 行，typescript，只读）
② tmp/ 相对路径（带前缀）+ line=3              → 会话工作区，光标落在行 3
③ 仅 ?session=                                 → 本会话工作区（入口按钮形态）
④ 无参数                                       → 项目/绑定根树（15 条目）

### 5.2 冲突合并（三窗格，第三轮补入）

对齐 IDEA Merge 的可用形态：左「我方（当前分支）」/ 中「合并结果（可编辑 Monaco）」/ 右「对方（合入分支）」，可选展开共同祖先（diff3 `base` 段）。

| 元素 | 行为 |
|---|---|
| 打开入口 | Git 面板冲突组的 `merge` 按钮 / 冲突行双击 / 右键「解决冲突（三窗格合并）」 |
| 冲突导航 | 「上一个 / 下一个」+「冲突 n/m · 我方 x 行 · 对方 y 行」（F8/F9） |
| 采纳 | 当前块：采纳我方 / 采纳对方 / 两者都留；整文件：全部我方 / 全部对方（二次确认） |
| 保存 | Ctrl+S，走 fs 写 + **etag 乐观锁**（外部改动 → 409 提示，不静默覆盖） |
| 标记为解决 | Ctrl+Shift+R，`git add` 后冲突态结束、面板冲突行消失 |
| 窄屏 | <1180px 三窗格纵向堆叠（每格太窄没法看代码） |

- **解析/替换为独立纯函数层**（`files/merge.ts`）：合并会**改写用户文件**，解析漏块或替换错行即静默损坏——因此必须能脱离 DOM/Monaco 单测（16 例）。容错取向：只把**完整闭合**的块算作冲突，畸形片段原样保留不参与解决。

### 5.3 界面结构改造（第四轮：三项反馈）

> 注：第四轮把 Git 面板从右栏移到**底部三栏**；第六轮（5.5）进一步把「变更内容」拆到左栏，底部只留「分支 | 日志 | 提交内容」，并移除标题栏。

#### ① 目录树 Git 状态（含一个「永远不显示」的缺陷）

**根因**：树首次渲染发生在 git 状态**异步到达之前**——`gitDecoration()` 读到的 `state.gitStatus` 还是 `null`，所有行都没有徽标；而 `refreshGit()` 拿到状态后只刷新了状态栏，没让树重画。只有手动刷新（F5/保存后）才偶然出现。

**修复**：`explorer.refreshGitDecorations()` —— 遍历既有行、只换装饰元素（徽标 + 状态类），**不重建树**（重建会丢展开态、滚动位置，并闪一下）。`refreshGit()` 成功与失败路径都回填。

**新增 IDEA 风格下划线**：文件名下方彩色线表示状态，与右侧字母徽标并存（颜色一扫便知、字母给精确状态）。用 `text-decoration` 而非伪元素：不占布局、不受省略号影响、选中文字时不错位。

| 状态 | 下划线 | 徽标 |
|---|---|---|
| 修改 | 工具色 `--tool` | `M` |
| 新增 / 未跟踪 / 已暂存 | 成功色 `--success` | `A` / `U` / `S` |
| 冲突 | 危险色 `--danger` | `!` |
| 删除 | 删除线（危险色） | `D` |
| 目录（子项有变更） | 中性色 | `•` |

#### ② 关闭按钮移入面板

原先在标签栏右侧（`.fw-tabbar` 的 actions 区），离面板很远。现改为**工具窗自己的标题栏**内（连同刷新按钮），并顺带把面板身份信息（「源代码管理」+ 当前分支 chip + 是否限定子目录 + 进行中的操作）一起放进标题栏。

#### ③ 面板挪到下方 + 三栏并排

- 右侧 `340px` 面板整体撤掉 → 编辑区下方**底部工具窗**（`.fw-git-dock`）。IDEA 的 Git 工具窗就在下方，横向空间比纵向充裕。

- 窄屏（<1180px）三栏纵向堆叠，工具窗整体滚动。

### 5.4 树上字母「看着像 q」的根因：line-height: 1 + overflow: hidden（第五轮）

用户反馈「目录树条目的 g 字母下半部没显示，看起来像 q」。**不是字体问题，是截断**。

```
.fw-tree { font-size: 12.5px; line-height: 1 }      ← 行盒 12.5px
字体度量：ascent 12 + descent 3 = 15px              ← 比行盒大 2.5px
半行距 = (12.5 - 15) / 2 = -1.25px                 ← 负值：墨迹上下都超出行盒
基线以下可用 = -1.25 + 3 = 1.75px
g 的墨迹下降 = 3px                                  ← 需要 3px → 被切 1.25px
.fw-tree-name { overflow: hidden; }                 ← 横向省略号所必需，纵向一并裁
```

两个可见后果（同一个根因）：

1. `keqing` 末尾的 `g` 下钩被切平 → 剩下的形状（碗 + 右侧直干）= **正好是 q 的形状**。字体度量更大的系统（Windows/macOS 的系统字体）切得更多，更明显。
2. **新加的状态下划线整条不可见**：下划线画在基线下方 2px + 1px 粗度 = 需要 3px，而只有 1.75px——**computed style 依然报 `text-decoration-line: underline`，实际一个像素都没画**。

**修复**：`.fw-tree { line-height: 1.55 }`（19.4px）→ 基线以下 ~5.2px，尾巴（3px）与下划线（3px）都完整；行高仍为 22px，视觉密度不变。

**A/B 实测（6x 放大 + 像素测量）**：

```
修复前 line-height=12.5px：基线以下 1.75px，g 尾巴需要 3px → 被切 1.25px
       文字墨迹 y = 60..113
修复后 line-height=19.4px：基线以下 5.19px                        → 完整
       文字墨迹 y = 60..117   ← 被裁的下半部回来了
```

**顺带修正的颜色语义**：下划线原用 `var(--tool)`——那是聊天里「工具消息」的颜色，在 acrylic 主题下是灰色（`#9a9aa6`），语义不符且不显眼。改为与 Git 面板变更字母同一套：修改=`--warning`（琥珀）、新增/未跟踪/已暂存=`--success`（绿）、冲突=`--danger`（红）、删除=红色删除线、「仅子项有变更」的目录=中性灰。

**为什么值得记一笔**：这是「computed style 通过、渲染不通过」的典型陷阱——查 computed style 会得到 `text-decoration-line: underline`，只有量**基线以下可用空间 vs 墨迹下降**或直接看渲染结果才能发现。同类风险：任何 `overflow: hidden` + 省略号的容器，只要 `line-height` 小于字体度量，就会静默裁掉 descender 与文字装饰。已扫描工作台其余同类元素（面包屑/标签标题/变更名/日志标题/分支名/状态栏）——line-height 均在 17.8px 以上，无此问题。

### 5.6 差异视图「上一处 / 下一处差异」导航

需求：差异视图要有跳转按钮，快速定位到下一处差异。

**做了什么**（`files/editor.ts` 的 `createDiffEditor` → `DiffHandle.nav`）：

- **工具条控件**：差异视图标题栏右侧一组 `⌃ 2 / 5 ⌄`——上一处、计数、下一处贴成一个控件组；无差异块时计数显示「无差异」且两个按钮置灰（看得见但不可用，不谜之失踪）。
- **快捷键**：`F7` / `Shift+F7`（同 IDEA），另加 `Alt+↓` / `Alt+↑` 作编辑器习惯的别名。快捷键只在**当前标签是差异视图**时生效；合并视图的 `F8/F9`（冲突块导航）语义不同，各管各的。
- **差异地图**：把概览尺（`renderOverviewRuler`）在差异视图里打开——右侧竖条标出全部差异的位置，配按钮用，一眼知道"还剩几处、都在哪"。普通编辑器仍关闭它。
- **反馈**：跳转时选中整个差异块并居中（`revealLineInCenterIfOutsideViewport`），编辑器获焦使选区高亮真正可见。

**三个踩过的坑**（都写进了代码注释）：

1. **Monaco 内置的 diff 快捷键会吃掉 F7**。Monaco 的 diff editor 自带 `diffReview` 的 `F7`/`Shift+F7` 绑定，并会 `stopPropagation`——所以宿主 `main.ts` 里那个冒泡阶段的全局快捷键在**编辑器获焦后**根本收不到 F7（表现是"点按钮能跳、按 F7 没反应"，且 Monaco 自己的行为与我们的计数不同步）。修法：在差异视图宿主上以**捕获阶段**挂 `keydown`（先于 Monaco 自己的监听器），拦下后自行处理。宿主那份全局快捷键保留，用于焦点不在编辑器内时（如焦点在工具条按钮上）。
2. **单行变更的"整块选中"是零宽选区**。原先 `startColumn: 1 → endColumn: 1`，同一行时是空的（等于一个光标），编辑器不画任何高亮 → 跳过去看不出来。改为末列取该行 `getLineMaxColumn`。
3. **纯删除块在 modified 侧行号为 0**，此时改在 original 侧定位（diff editor 两侧滚动同步，露一边两边都跟）。

**一个刻意的行为选择**：计数以**视口**判定（视口顶部所在/之后的那一块算"当前"），所以用户手动滚到哪里，计数就跟到哪里——而不是维护一个看不见的内部游标。代价是"打开即按 F7"时若第一处差异本就可见，画面不会动（但会让它被选中、计数不变），这与 VSCode 的 diff 导航一致；再按一次即到第二处。到头**回卷**（连点不会没反馈地卡住，同 IDEA）。

**验证**（Playwright，200 行文件、5 处分散差异 + 零差异对照）：

```
差异编辑器已挂载：true
导航计数（初始）：1 / 5        按钮：["上一处差异（Shift+F7）","下一处差异（F7）"]
  初始 → 1 / 5，视口首行 1
  点「下一处」×3 → 2 / 5（首行 38）→ 3 / 5（首行 88）
  F7 → 4 / 5（首行 138）；Shift+F7 → 3 / 5；Alt+↑ → 2 / 5
  连点到底 / 连点到顶 → 双向回卷正常
  滚到文件末尾 → 计数 5 / 5（跟着视口走）；再点 → 回到 1 / 5 并居中
零差异对照（chmod 改了权限位、内容逐字节相同）：
  计数「无差异」，两个按钮 disabled=[true,true]
概览尺：5 处标记（红=删 / 绿=增）+ 当前块高亮
控制台零错误
```

### 5.7 布局与导航收口（第七轮：四项反馈）

#### ① 活动栏：变更下移、去掉「打开文件夹」

上组三视图的顺序改为 **资源管理器 → 搜索 → 变更**（前两个是"找文件"，变更面板是"看待提交的改动"，符合从导航到动作的顺序）。「打开文件夹（切换根）」按钮删除——切根在资源管理器顶部的根选择按钮里本来就有，且那里才带根清单与面包屑语义，两个入口反而让人犹豫。

#### ② 底部工具窗占满整宽，左栏只占上部

```
改前： .fw-app > .fw-body > [rail, left, center(tabbar, views, dock, resizer)]
改后： .fw-app > [ .fw-body > [rail, left, center(tabbar, views)], resizer, dock, statusbar ]
```

底部工具窗从编辑区里**搬到外壳层**，成为整宽的兄弟节点（同 IDEA：打开底部工具窗时，左侧 Project 工具窗的高度被压缩，而不是并排）。

为什么值得改：底部三栏（分支 | 日志 | 提交内容）看的是"历史/提交"这类全局信息，与左边在看哪个目录无关；占满整宽后三栏才有足够横向空间；同时左栏内容（目录树/改动列表）本来就是纵向长列表，少几十像素高度不痛。

实测（1680×1000）：`dock x=0→1680`（贴左边缘、到右边缘）、`dock.top=676`，而 `左栏底=672`、`rail 底=672` —— 左栏与活动栏都只在上部，互不重叠。

#### ③ 移除面包屑与工具条行，动作全部收进标签栏（仅图标）

原来标签栏下面还有一行：左侧是路径面包屑（`根 > src > file.ts`），右侧是文字按钮（查看/编辑、保存、渲染预览、下载、历史）。

- **面包屑删除**：它在回答"我在哪"，而标签标题给的是文件名、资源管理器给的是目录位置与选中态；一行 36px 常驻只为重复这两个信息，不划算（还要处理超长路径的省略）。
- **按钮收进标签栏右侧**（`tabActions()`），**全部仅图标**，靠 `title` 说明；按钮随活动标签类型变化：
  - 文件标签：编辑/查看、保存（有改动时高亮）、渲染预览（仅图表源文件）、下载、文件历史、重新加载、复制路径
  - 差异标签：见 ④ 的两组导航
  - 合并视图标签：**不给按钮**（它自带冲突导航/采纳/保存/标记工具条，重复反而乱）
  - 比较视图标签：不给（自带端点选择与交换控件）

补回两处因删行而丢失的重渲染：`loadTab` 末尾与 `toggleMode` 里原来各有一句 `renderToolbar()`，现在动作住在标签栏，跟着改成 `renderTabbar()`（否则编辑态切换后图标不变）。

#### ④ 「上一个 / 下一个变更文件」

标签栏上两组导航，**箭头方向区分语义**：左右 = 换文件（跨文件），上下 = 换差异（文件内）。

- 变更文件清单按**与当前差异相同的端点对**取（`gitCompare`），所以工作区改动、某次提交、任意两端比较都能用同一套按钮遍历。
- 语义是**同一个标签内换文件**（不是每个文件开一个标签）：遍历 20 个文件不该堆 20 个标签。因此换文件时给标签改 key（标签 id 含路径，`rekeyTab` 同步 `viewHosts` 与 `activeId`）；若目标文件的差异标签已开着则直接切过去，不重复开。
- 标签标题沿用原标题的"来源后缀"（`（工作区）`/` @ 3a43d50b`），只换文件名部分——原格式是各调用方精心取的，不该被导航改掉。
- 到头**双向回卷**（同 5.6 的差异导航）。
- 快捷键 `Ctrl+Alt+↓ / Ctrl+Alt+↑`；**不用更顺手的 Alt+←/→**——那是浏览器前进/后退，会把工作台整页导航走。

**踩到的两个坑（都已写进注释）：**

1. **compare 端点与 content 端点的参数约定不同**——`DiffEndpoints` 里现在显式分成 `originalRef/modifiedRef`（取内容：`gitContent`，支持 `WORKTREE`/`INDEX`/rev）与 `compare`（取文件清单：`gitCompare`，其端点是一张语义表）。把内容端点直接喂给 compare，「未暂存」会从 `from=INDEX&to=WORKTREE` 被解释成 `--cached`（HEAD↔暂存区）——**不报错，只是静默返回另一批文件**，于是按钮一直置灰。正确写法是 from 留空、`to=WORKTREE`（`git diff`）。这类"两个端点语义相近但不同"的地方最容易埋雷，所以把两种形式放在同一个接口里显式标注。
2. **`Ctrl+Alt+↑/↓` 是 Monaco 的多光标快捷键**，编辑器获焦时事件到不了冒泡阶段（与 5.6 里 F7 的坑同源）。跨文件导航单独用**捕获阶段**监听——它是"看代码"时的高频动作，不该因为焦点在编辑器里就失灵。

② dock x=0→1680（整宽）、top=676；左栏底=672、rail 底=672（都只在上部，不重叠）
③ .fw-toolbar=0、面包屑元素=0；文件标签 6 个按钮全部 icon=true、text=""
④ 打开 a1.ts 差异 → 1/3；点「下一个」→ b2.ts 2/3 → c3.ts 3/3；

### 5.8 入口图标重画 + 分屏打开（第八轮：两项反馈）

#### ① 图标重画：与同级按钮同一「实心」语言

原标题栏按钮是**描边 2px 的文件夹 + 内部 `<>` 三段路径**，放在两个**实心**同级按钮（☰ 会话列表、▦ 轮盘）之间，重量明显偏轻、细节也偏多。重画为**实心文件夹 + 掏空尖括号**（`fill="currentColor"` + `fill-rule="evenodd"`，单条 path）：与兄弟按钮同一重量，同时保留「文件 + 代码」的双重语义。

判断依据不是主观观感，而是**把 16px 光栅化后最近邻放大 8 倍**逐一比对（描边图形在小尺寸下的糊、断、错位只有按像素看才准）。同一个脚手架里也试了「实心文件夹 + 斜杠」「IDE 窗口」两案：前者代码语义弱，后者与轮盘的 ▦ 撞形，都淘汰。

#### ② 默认新标签 + 悬浮分屏

- 主按钮行为不变：**新标签打开**（重量级 IDE 式页面，与聊天并行使用是常态，且故障隔离）。提示语补上「· 新标签打开」表明意图。
- 按钮下缘 hover 弹出副按钮（与轮盘同一交互语言：hover 展开、离开收起），点击进入**分屏**：右侧 iframe 嵌工作台，左侧主视图**折叠会话列表**，默认**五五开**，分界可拖、双击复位。

**两个必须用「逐步移动指针」才测得出的坑：**

1. **悬浮副按钮点不到**：主按钮与副按钮之间有 6px 空隙，指针穿过时 `:hover` 丢失 → 副按钮立刻 `pointer-events:none` 并淡出。自动化里 `locator.click()` 是瞬移（不经过空隙），测试全绿但真实用户点不到。修法：`.files-entry::after` 透明「桥」盖住空隙 + 隐藏侧 `transition-delay: 0.12s` 宽限；回归测试改为 `mouse.move` 逐点移动再点击。
2. **提示气泡正好压住副按钮**：标题栏贴顶（上方无空间），气泡必然落在按钮下方——与副按钮同一位置。给 tooltip 加 `data-tip-pos="left"` 放置选项，文件工作台按钮的提示改为贴左侧，与下方的副按钮互不遮挡。

#### ③ 实现要点

- `files-split.ts`（新）：面板构建、拖动、状态、跨界桥接；`css/files-split.css`（新）：入口 hover 与分屏布局。
- **iframe 而非组件化**：工作台本就是独立入口（Monaco + Git + 完整状态模型），iframe 保住单实例、故障隔离与状态独立（滚到哪、开了哪些标签、底部工具窗高低都是它自己的事）；代价只是两个跨界动作要桥接。
- **布局**：`#app` 在分屏时改为 `1fr var(--files-split-w, 50vw)`（会话列表 `display:none`），面板作为网格第 2 列的第 2 行，标题栏仍横跨整宽。
- **关闭不销毁 iframe**（只 `hidden`）：IDE 里工具窗关掉再开也是原样；重新加载一次要重建 Monaco/Git 状态，几秒白屏不值当。宽度持久化、**打开状态不持久化**（页面加载即拉起一个重工作台，对多数访问是浪费）。
- **拖动**：宽度 = 窗口宽 − 指针 x，钳制在 [360px, 窗口宽−420px]（两侧都要能看）；且 `pointerup` 同时挂在窗口**捕获阶段**——指针进入 iframe 后事件由 iframe 自己的文档接管，拖条收不到松手会「粘住」。
- **桥接只做两件事**：主题同步、关闭。工作台在嵌入态把「返回歌白主界面」换成「关闭分屏」（否则会把 iframe 导航到主界面）。
- 附带：分屏时点「会话列表」按钮 = 退出分屏把列表拿回来（否则该按钮在分屏期间形同死去）；`Ctrl+Shift+E` 改为**开关分屏**（同 VSCode 的「显示/隐藏侧边编辑器」，连按两次不该攒出两个标签页）。

**顺手修掉两个真 bug：**

- `theme-core`：`setCnyScheme` / `setAcrylicLt` 以前**不发** `gebai:theme-change`——只改主题 id 才通知。于是主界面把人民币面额改成 50 元（翠绿）时，分屏里的工作台仍是 100 元红（这个坑在 5.5 的主题共用里修过一次，但只修了「进页面时读不读」，没修「改的时候通不通知」）。现在三种改动统一走 `notifyThemeChange()`。
- `theme-core`：分屏后切主题必然出现 `AbortError: Transition was skipped` —— 页面里有 iframe 时 Chrome 会跳过 View Transition，而其 `ready` 的 rejection 没人接，直接打进控制台。现在 `vt.ready.catch()` 接住（跳过只是没动画，`swap` 照常执行、主题照常生效）。

**验证**（Playwright，1600×950，控制台零错误）：

### 5.9 入口恢复原状 + 独立关闭按钮 + 无标题栏面板 + 活动栏全高（第九轮：三项反馈）

#### ① 分屏激活时入口「恢复原状」，关闭交给独立按钮

此前分屏一开，入口的副按钮就变成 ✕ 并**常驻**——同一个位置既开又关，图标还会变形。现在：

- 副按钮**永远是分屏图标**（不变形），并且**仍然只在 hover 时出现**（不常驻）；
- 标题栏新增**独立的关闭按钮**（`#files-split-close`，✕ 描边——与入口那个实心分屏图标在视觉上明确区分"开/关"两个动作），仅在分屏激活时出现，关闭即隐藏；
- 主按钮不再随分屏态高亮（`active` 类去掉）——状态由关闭按钮的存在来表达就够了。

顺带修掉一个焦点陷阱：指针点击副按钮时 `:focus-visible` 为 false，按钮淡出后**仍握着焦点**——此后随手按 Enter/空格会把分屏"隐形地"再切一次，聚焦提示气泡也悬着不散。改为指针触发的点击结束后主动 `blur()`（键盘触发时保留，`:focus-visible` 会让它继续显形）。提示语也补上快捷键（键盘用户靠 `Ctrl+Shift+E`，因为它不再常驻）。

#### ② 分屏面板去掉标题栏（纯容器）

那条 30px 横条要花掉整个编辑区的垂直空间，而它里面三个按钮各有更好的去处：

| 原按钮 | 去处 |
|---|---|
| 关闭 | 标题栏的独立关闭按钮（=①） |
| 打开（新标签） | 入口主按钮本身就是这个动作 |
| 重新加载 / 在新标签打开 | 挪进工作台自己的「更多」菜单（页面级动作归页面自己） |

于是面板只剩 `[分界拖条, iframe]`，工作台完全接管那片空间（它自己就是 IDE 式界面，自带顶栏与状态栏）。实测 `iframe y=44` = 主界面标题栏高，高度差 0。

嵌入态的工作台「更多」菜单因此多了两项：**重新加载工作台**（`location.reload()`）与**在新标签打开**（`postMessage` 回宿主执行，自己 `window.open` 会丢宿主侧的参数上下文）。

**Esc 的作用域**：父文档监听 Esc 关分屏（焦点在主界面时有效）；`iframe` 里的按键父文档收不到，故子页也转发一次——但必须挂**捕获阶段 + 事前检查有没有浮层**，不能简单地在冒泡阶段转发：菜单/对话框的 Esc 处理器都在冒泡阶段且**不** `stopPropagation`，等它们关完菜单再判断，DOM 里浮层已经没了，分屏会跟着一起关（实测：只想关菜单却把整个工作台也关了）。

#### ③ 活动栏贯穿全高，底部工具窗不再压住它

```
改前： .fw-app > [ .fw-body{rail, left, center}, dockResizer, dock, statusbar ]
改后： .fw-app > [ .fw-main{ rail, .fw-right{ .fw-body{left, center}, dockResizer, dock } }, statusbar ]
```

活动栏是**唯一贯穿全高**的一列：视图切换 / 工具窗开关这类入口要在任何面板开合时都待在原位，被底部工具窗截断半截会让"下方那几个按钮"看起来像工具窗的一部分。底部工具窗则从活动栏右侧开始（横跨左栏下方到窗口右缘），左栏仍只占上半部分。

同 IDEA：打开底部工具窗时左侧 Project 工具窗被压矮而非并排；活动栏始终完整。

顺带修掉拖工具窗时的偏移：高度原本按 `window.innerHeight - e.clientY` 反推，但工具窗底边是**状态栏上沿**（状态栏在它下面），差值恰是一个状态栏高度，表现为拖动时工具窗比指针慢一拍。改为按 `statusbar.top - e.clientY` 计算。

**验证**（Playwright 1440×900，控制台零错误）：

```

   分屏已开：副按钮图标仍是分屏图标、opacity=0（不常驻、不变形）；关闭按钮 hidden=false 且出现在标题栏
   点独立关闭按钮 → 关闭按钮重新 hidden、面板隐藏
② 面板子元素=[files-split-resizer, files-split-frame]（无横条）；面板 top=44、iframe top=44 → 高度差 0
   工作台「更多」菜单（嵌入态）含「重新加载工作台」「在新标签打开」「关闭分屏」

### 5.10 入口移到标题栏左侧 + 空心图标 + 修窄面板展示错乱（第十轮：四项反馈）

#### ① 入口移到标题栏左侧，悬浮副按钮改到右侧

`#files-entry` 从 `.header-right` 挪到标题栏最左（会话列表按钮 ☰ 的右边）；副按钮从"下方弹出"改为**右方弹出**（`left: 100% + 6px`，垂直居中），透明"桥"也随之从竖向改横向（`::after` 的 left/top/bottom/width 一套）。提示气泡不再需要 `data-tip-pos="left"`（副按钮在右边，与下方的气泡互不遮挡），该属性保留在 ui.ts 里供其它入口使用。

#### ② 图标改空心

从"实心文件夹 + 掏空尖括号"改为**描边（stroke 1.9 / 24 viewBox）+ 空心文件夹轮廓 + `<>` 两笔**（`fill="none"`，3 条 path）。
判断依旧不靠观感：把 16px 光栅化后最近邻放大 6 倍看笔画——1.9 的描边在 16px 下约 1.27px 设备像素，轮廓与 `<>` 都能干净分开，没有糊成一团。

#### ③ 修「半宽多一点时工作台展示错乱」——**这是我上一轮引入的回归**

现象：分屏面板在 ~1000px 以下时，工作台内部整块错位（编辑区被压成 33px 宽）。

根因是**类名撞名**：上一轮我给"活动栏右侧的整块包裹"用了 `.fw-right`——而这个类名是**已废弃的"右侧 Git 面板"**用过的，CSS 里还留着一条针对它的窄屏规则：

```css
@media (max-width: 1080px) { .fw-right { position: absolute; right: 0; top: 34px; bottom: 24px; ... } }
```

Git 面板迁到下方工具窗后，这条规则成了死代码——直到我把新包裹类也叫 `.fw-right`，它就被"复活"了：≤1080px 时包裹被绝对定位成一条 277px 宽的抽屉，编辑区只剩 33px。半宽（1600/2=800）恰在这个区间，所以"一半多一点就不能看"。

处理（两手都做，不留同类隐患）：

1. 把死规则删掉（只保留其中仍有效的 `.fw-left { width: 240px }`）；
2. 新包裹类改名 `.fw-main-right`，并在 CSS 与 TS 两处写明"**不能**叫 `.fw-right`"的原因。

实测（面板宽 → 编辑区宽）：改前 1000→33、860→33、800→33、700→33（全是绝对定位）；改后 1000→712、860→571、800→512、700→411、460→171，且各档**横向溢出均为 0**。

#### ③b 顺带修掉两处窄屏相关的死代码/隐患

- **Git 三栏的"窄屏纵向堆叠"规则从来没生效过**：它设的是 `grid-template-columns`，而 `.fw-git-cols` 是 **flex** 容器（死代码），于是窄屏下三栏各自 `flex: 0 0 auto` + 固定宽度直接横向溢出。改为 `flex-direction: column` + 各栏 `width:auto/min-width:0/min-height:180px`。
- **断点从 1180px 改到 700px**：分屏常在"半宽多一点"用，那时工具窗还有 ~815px，三栏（200 + 弹性 + 240）摆得下且有富余；按 1180 堆叠反而把好用的三栏拆成一列高塔。按"三栏所需最小宽"定：`refs 200 + log ≈160 + commit 240 ≈ 600`，工具窗宽 = 面板宽 − 活动栏 44，故取 700px（面板 700 → 工具窗 656）。实测 860 → `flex-direction: row`、三栏 200/337/277；600 → `column`、三栏 556×180。
- **状态栏是窄面板下真正的横向溢出源**（它自己就顶出 159px，把文档撑出滚动条）：条目全是 `nowrap` 且不肯收缩。改为按**优先级**退让——`renderStatus` 给每条打 `data-pri`（1 最要、3 最先隐），CSS 在 ≤900px 隐 pri3（编码/EOL/大小/时间/Monaco 内核）、≤700px 再隐 pri2（语言/行列）；状态栏本身加 `overflow:hidden` 兜底。为什么要显式标：条目随文件类型动态增删，用 `:nth-child` 猜"哪几个能藏"会错位。实测 900/860 → 可见 5 条；700/640/460 → 3 条；各档溢出 0。

#### ④ 关闭按钮留在原位置

`#files-split-close` 仍在标题栏**右侧**（轮盘左边），不随入口移到左边——入口那组永远只表达"打开"，关闭按钮是一个独立、位置固定的目标。实测分屏激活时 x=1510..1542（1600 窗口）。

## 8. 已知边界与后续可选增强

- Office 预览依赖服务端转换，复杂排版（图表、批注）不保证像素级一致 → 提供「下载打开」兜底。
- 超大文件（>10MB）默认只读片段并提示下载；二进制无内置十六进制编辑（定位是查看器而非 hex 编辑器）。
- 视频仅浏览器原生可解码格式（mp4/webm；H.265 视浏览器而定）。
- 合并冲突解决目前是「三方内容查看 + 用编辑态改文件 + 标记已解决」，未做专门的三窗格合并编辑器。
- 未做：多根同时打开（一次一个活动根，多标签跨根可开）、Git 子模块详情、LFS 管理、提交图的无上限虚拟滚动（当前分页加载）。
