# 格斗（gedou）—— 类拳皇的 2D 对战示例

> **这个示例检验什么**：别的大多数示例检验"控件正确"；本示例检验的是**连续动画 +
> 实时输入 + 判定几何**这一路——每帧重绘的自绘组件、固定步长逻辑帧、按键"按住"与
> "边沿"两种语义、以及"看得见的画面"与"算得准的判定"必须各归其位。

## 跑起来

```bash
st build gedou                 # 构建
./build/dev/bin/gedou          # 有桌面就直接玩

# 无头驱动（截图 / 自动化）
./build/dev/bin/gedou --headless --control-port 0 --control-file ctl.json --shots shots/
py -3 tools/gedou_e2e.py       # 端到端回归（7 组断言）
py -3 tools/gedou_reverse_verify.py   # 逆向验证：逐条回退，确认断言真能变红
st test gedou                  # 单测（31 条：姿态几何 + 战斗不变量 + 六个技能机制）
```

| 操作 | 键 |
|---|---|
| 移动 | `A` / `D` |
| 防御 | `S` |
| **三个技能** | `J` / `K` / `L` |
| 必杀（耗槽） | `U` |
| 暂停 / 显示判定盒 / 重开 | `P` / `H` / `R` |
| 选人界面：选角色 / 切焦点 / 确认 | `←→` / `Tab` / `Enter` |

> `J/K/L` 是**三个技能位**，含义随角色变（见下表）。不是"轻拳/重拳/蹬腿"——
> 那两个技能型角色手里根本没有这些招。底部的提示条会显示当前角色的技能名。

命令行：`--difficulty easy|normal|hard`、`--left N --right N`（角色档 0~1）、
`--dummy`（训练桩：对手不动）、`--paused`（暂停启动，截图用）、`--hitbox`（判定盒）、
**`--policy FILE`（用训练好的神经网络策略接管对手）**、
**`--ai-vs-ai`（跳过选人直接机机对战）**、**`--record <目录>`（逐帧存 PNG 供 ffmpeg 合成视频）**。

> 对手可以由**强化学习训出来的网络**接管：
> ```bash
> ./build/dev/bin/gedou --policy apps/gedou/policy-ppo.json
> ```
> 训练方法、实测胜率（**100% vs 手写 AI 35%**）与全部踩过的坑：**`RL.md`**。

## 两个角色

| # | 名字 | 定位 | J（技能 1） | K（技能 2） | L（技能 3） |
|---|---|---|---|---|---|
| 0 | 甜甜圈 | 技能型 | **真好吃**（抛甜甜圈） | **泡芙**（扇形喷射） | **摸腰**（冻结 2 秒 + 扣半血） |
| 1 | 户圣 | 忍耐型 | **苹果手机**（天降苹果） | **苹果小区**（护盾反弹） | **苹果人生**（变身回血减伤） |

两个角色各带**专属招式**，没有"轻拳/重拳/蹬腿"这类通用招。

### 美术素材怎么来的

角色立绘是**AI 生成**的（SDXL 动漫模型 + Illustrious 专用 OpenPose ControlNet），
每个动作一张，共 34 张内嵌进二进制。

> 完整方案、为什么换掉其他三条 ControlNet 路线、以及全部踩过的坑：
> **`ART_PIPELINE.md`**。

### 六个技能的机制

| 技能 | 机制 | 关键数值 | 平衡手段 |
|---|---|---|---|
| 真好吃 | **投射物**：出手即生成，独立飞行、独立判定 | 飞 90 帧、命中 58 | 自己本体不伤人（纯飞行物） |
| 泡芙 | **扇形锥判定**：以角色为顶点、张角 30°、射程 240px | 每段 26，最多 4 段 | 单段伤害低，靠多段压制 |
| 摸腰 | **冻结 2 秒**（120 帧）+ **扣 50% 最大血** | 40 + 50% × max_hp | **前摇 22 帧 + 收招 30 帧**（全场最慢）、射程极短、可挡 |
| 苹果手机 | **落点预警 + 延迟落下**（可躲） | 预警 24 帧 | 站着必中、跑开就空 |
| 苹果小区 | **护盾**：格挡全部正面伤害并反弹 60% | 持续 150 帧 | 不是攻击招（自己不伤人） |
| 苹果人生 | **变身**：每帧回血 1.4 + 减伤 60%，但完全不能动 | 180 帧（3 秒） | 拿 3 秒主动权换血 |

> **冻结不可刷新**（重要）：已冻结时再次被摸腰**不会重置计时**。
> 否则「摸腰 → 冻 2 秒 → 期间再摸一次」就是永久封印——实测踩到：
> 连按 37 次摸腰，对手一次都没还手，比赛 4000 帧打不出结果。

## 分层（本示例的主要教学点）

| 层 | 文件 | 职责 | 能被什么断言 |
|---|---|---|---|
| 姿态 | `pose.*` | 招式关键帧 → 骨架关节（**纯函数**） | 单测（对称性/单调性/脚在地面） |
| 数据 | `fighter.*` | 角色档案 + 招式数值表 | 单测（距离由姿态反算） |
| 逻辑 | `fight.*` | 60Hz 状态机：判定盒/伤害/硬直/回合 | 单测 + e2e |
| 对手 | `ai.*` | 产出与键盘**同一个** `Intent` | 单测（确定性、阈值单位） |
| RL | `rl_env.*` / `policy.*` | 观测/动作/奖励契约 + 权重推理（**逻辑仍只一份**） | 单测（契约/前向逐值/自我中心） |
| 视图 | `game_view.*` | 画场地/地板/HUD/特效 | 只能看截图（+ 像素哈希） |
| 美术 | `fighter_art.*` / `char_portrait.*` | 矢量角色 / AI 立绘（见 `ART_PIPELINE.md`） | 截图 |

**分层不是为了好看**：格斗游戏最容易坏的地方（判定位置、帧数、朝向、伤害）都**看不见**。
把它们放进一个不认识画布的 `Match`，才能用"3 帧后命中、血量掉 42"这种断言钉住；
反过来视图层不改战斗状态，"画面看着打到但血量没动"这类问题才不会互相掩盖。

## 三个关键约定

### 1. 逻辑帧率固定 60Hz，与渲染帧解耦

`GameView::paint_content` 按 `RenderContext::time_seconds` 累积时间，每满 `1/60 s`
推进**一个**逻辑帧（最多补 4 帧，防挂起后一次性补上万帧）。低帧率机器上判定不会变慢，
测试也能用 `invoke step N` 完全可复现地快进。

### 2. 招式距离由**姿态**反算，不手填

`reach_far` 取自命中帧的"四肢最前点"（`strike_reach`）。手填数字时改一个姿态就得记得
同步改表——实测忘过一次，四个招式全偏，症状是**两种反向的假命中**：
盒比手远（空挥也命中）／手比盒远（看着打中了却没判上）。

### 3. AI 与玩家走**同一个** `Intent`

AI 每帧产出一个 `Intent`，和键盘折算出来的结构完全相同。于是"AI 能做的事玩家都能做"
是结构保证，不会出现"AI 用了玩家没有的隐藏机制"这种调不平的手感问题。
AI 用**自带的确定性 LCG**（不是 `std::rand`）：同种子跑出同一场对局，测试才能断言。

## 控制通道面

`#arena` 元素（`get`/`set`/`invoke`）：

- **读**：`state`（JSON 全量快照：双方位置/血量/槽/招式/判定盒 + 招式表）、
  `logic_frames`、`phase`、`left_move`/`right_move`、`left_hp`/`right_hp`、
  `left_meter`/`right_meter`、`left_hitbox`/`right_hitbox`、`banner`、`winner`、`error`
- **写**：`paused`、`show_hitbox`、`dummy`、`ai`、`difficulty`、`player_side`
- **动作**：`attack <light|heavy|kick|special>`、`opponent_attack <...>`、`charge`、
  `damage <side>`、`step <N>`、`restart`、`pause`/`resume`、`guard`

`invoke attack` 失败时会带上原因（`error` 属性）：**必杀槽不足**与**硬直中**是两件事，
把它们合并成一个 `handled=false` 会让调用方只能靠猜。

## 踩过的坑（都在代码注释里带实测数据）

| 现象 | 根因 |
|---|---|
| 角色悬空 | 脚踝局部 y 写成 8（应为 0）——"谁会去量脚底"正是单测存在的理由 |
| 手臂"不见了" | 两条手臂同源从躯干中线出发，视觉上糊成一坨 |
| 腰带像肚子挂了个球 | 腰带沿**躯干方向**画，应沿垂直方向 |
| 背景一圈圈同心圆 | 用多层同心圆近似径向光晕，环间留下可见色阶台阶 |
| 蹬腿像"抬着膝盖" | 胯→膝→足不单调（膝比脚还靠外） |
| AI 出手距离偏小 40% | 拿世界像素间距去比招式表的**局部单位**距离 |
| 胜者看不出赢了 | 胜利姿态被"空闲 → 切回 Idle"的分支冲掉 |
| 拖窗口会清空战况 | 重排时重建了 `Match`，应只改场地几何（`set_arena`） |
| 骨架线被画进画面 | 通用 ControlNet 是写实数据训的，动漫模型理解不了 | 换**同底模**的 ControlNet |
| 姿势完全不受控（还不报错） | `control_mode` 参数 diffusers 不支持 | 用单一模式的专用 ControlNet |
| 三个种子都在鞠躬 | `standing upright` 在动漫数据里对应鞠躬 | 给具体手部动作（插兜） |
| 抠图后脸上有黑洞 | 按亮度判透明，皮肤和白鞋被当背景 | 改**泛洪法**（只挖与边框连通的白色） |
| 立绘在夜景里"陷进背景" | 白底图与深色舞台对比过强 | 脚下加径向光晕（不是调贴图亮度） |

## 与其它示例的分工
- `gallery`：控件陈列（每样东西长什么样）
- `gbcode`：大界面（多面板/编辑器/终端协同）
- `caiyun` / `louyue`：离屏出片（结果是一张图/一段视频）
- **`gedou`：实时**（结果是每秒 60 次的判定 + 每帧重绘）
- 美术素材的 AI 生产流水线单独写在 **`ART_PIPELINE.md`**
