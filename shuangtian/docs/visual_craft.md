# 视觉制作手册（裁云 · 三维画面）

> **适用场景**：做「看起来专业」的三维画面/短片（产品展示、图标动画、界面演示）。
> **不适用**：判断"能不能跑"——那是测试的事。
>
> **为什么单独立一份**：本仓的 `perceptual_changes.md` 解决的是"**改**已有观感"，
> 而这份处理"**从零做**一段画面"——两次都发生过的失败形态不同。
> 实测代价（2026-10-22）：第一版三维片子被用户判为「太原始粗糙」，
> 复盘发现**违反了下表 6 条中的 5 条**，而每一条都是动画/图形学界有名字的成熟原则。

---

## 0. 一句话总纲

**"看起来专业"不是"多边形更多"，而是"物理一致 + 节奏正确 + 有意图"。**
多边形再多，缺了接触阴影、缺了 squash、动作匀速、配色随机，仍然是"粗糙"。

---

## 1. 六条硬约束（每条都有名字、有出处、有实测代价）

### 1.1 接触阴影：物体的"落地感"来自它与地面之间那片暗

| | |
|---|---|
| **来源** | GPU Gems Ch.11（影子贴图）；AO 的感知作用是"better perception of the 3D shape" |
| **原理** | 三维形状靠**明暗差**被感知。物体与地面接触处若两侧同亮，大脑判"贴纸" |
| **实测代价** | 我的第一版：图标块与桌面块**没有任何阴影**，两物体亮度接近 → 判"原始粗糙" |
| **判据** | 物体正下方必须有**比周围地面更暗**的一片，且随离地距离**变大变淡** |

**三个层次（按代价递增）**：

| 做法 | 成本 | 效果 |
|---|---|---|
| **Blob shadow**：物体投影到地面画一个模糊椭圆 | 极低 | 解决 80% 的"漂浮感"——**先做这个** |
| 屏幕空间接触阴影（SSAO 局部化） | 中 | 缝隙处的暗部，物体互相接触时更真 |
| 影子贴图（Shadow map） | 高 | 真软阴影；需深度图 + bias + PCF |

### 1.2 Squash & Stretch：形变是"有重量"的唯一视觉证据

| | |
|---|---|
| **来源** | Disney 12 原则之首（Thomas & Johnston, 1981） |
| **原文要点** | "the most important aspect of this principle is that an object's **volume does not change** when squashed or stretched"——**体积守恒** |
| **实测代价** | 我的第一版：立方体上下平移、形状**完全不变** → 判"像贴纸在移动" |
| **判据** | 落地瞬间 Y 压扁 **×0.88** 的同时 X/Z 必须鼓 **×1.06**（体积≈守恒） |

**必须成对**：只压扁不鼓 = 漏气；只鼓不压 = 膨胀。且**接地点被压扁时，物体底部不能穿进地面**（要用"底部贴地"重新定位，不是中心缩放）。

### 1.3 Arcs：所有自然运动都是弧线

| | |
|---|---|
| **来源** | Disney 12 原则 |
| **原文要点** | "animation should adhere to this principle by following implied **arcs**"；例外是"mechanical movement, which typically moves in straight lines" |
| **实测代价** | 我的第一版：图标只做**竖直**弹跳（严格直线）→ 显得机械 |
| **判据** | 有位移的弹跳，轨迹必须带横向分量 + 弧高 |

### 1.4 Ease / Timing：速度不能均匀

| | |
|---|---|
| **来源** | Disney 12 原则（Timing / Slow in & slow out） |
| **原文要点** | "more pictures are drawn near the extreme poses"——极值附近要更多帧 = 更慢 |
| **实测代价** | 我的第一版：`|sin|` 是**纯正弦**，顶点与地面速度都最快 → 违反真实抛体（顶点最慢、落地最快） |
| **判据** | 抛物线用 `4h·t(1-t)`（物理正确），**不要**用 `sin` |

### 1.5 Anticipation + 回弹过冲

| | |
|---|---|
| **来源** | Disney 12 原则（Anticipation） |
| **原文要点** | "prepares for the action by winding… a dancer jumping has to bend the knees first" |
| **实测代价** | 我的第一版：一开始就跳，无预备 |
| **判据** | 起跳前有**下蹲**（压扁）；落定后有**过冲**再回来（1~2 帧的反向小位移） |

### 1.6 配色：**统一色相族 + 一个强调色**

| | |
|---|---|
| **来源** | 产品设计通例；裁云自己的品牌色是 `#4D6BFE` |
| **实测代价** | 我程序生成的桌面用了 12 色**彩虹**调色板（蓝青绿黄橙红紫粉…）→ 判"粗糙"（廉价感） |
| **判据** | 辅助色只允许**同色相不同明度**；跨色相只留给**唯一**强调元素 |

## 2. 七步出片循环（从零做一段画面时按这个顺序）

```
① 定参照     先找同类的**专业作品**截图（产品视频/动效），不用文字描述"好看"
② 写量尺     至少 2 个正交量（见 §3）；先验证尺子能分辨"已知好/已知差"两张图
③ 骨架       只做几何与构图（无阴影无动效），出静帧看"像不像"
④ 落地感     加 blob shadow（§1.1 第一层）——这一步的收益最大
⑤ 动效       加 squash/stretch + arc + ease（§1.2~1.5）
⑥ 材质       加侧壁渐变/边缘高光/配色统一（§1.6）
⑦ 三方对比   把**改前 / 改后 / 参照**并排给用户，标数字，请他确认方向
```

**每步都要能独立回退**：先把工程提交到一个干净状态，再逐步加。否则失败时无法归因。

---

## 3. 量尺（至少两个正交量，互不蕴含）

| 量 | 定义 | 对应用户说的 |
|---|---|---|
| **接触暗度** | 物体正下方区域亮度 / 同场景无阴影时该区域亮度 | "像贴纸/飘着" |
| **形变幅度** | 落地帧的 Y/X 比例偏离 1 的程度 | "死板/僵硬" |
| **路径弯曲度** | 轨迹最大横向偏移 / 竖直位移 | "机械/假" |
| **色相数** | 画面中**色相差 > 30°** 的独立色族数 | "花/廉价" |
| 边缘对比 | 物体轮廓处的梯度峰值 | "糊/脏" |

**互不蕴含的证明**：阴影很真（①高）但形变为 0（②低）→ "有落地感但僵硬"；
形变很足（②高）但配色花（④高）→ "活泼但廉价"。**任何一项高都推不出其他项。**

## 4. 反模式（每条都害过我）

| 反模式 | 后果 |
|---|---|
| **"加多边形/加分辨率"当解法** | 形状感知靠**明暗**，不靠密度。几何再细，无阴影仍是贴纸 |
| **只做位移，不做形变** | 一切物体都像刚体卡片在滑 |
| **阴影与物体同亮度** | 等于没有阴影；阴影必须**显著更暗**（建议 55~65% 亮度） |
| **程序化生成 = 随便配色** | 随手 12 色 = 廉价。调色板是要设计的 |
| **用 `sin` 当弹跳** | 违反抛体物理（顶点应最慢）。用 `4h·t(1-t)` |
| **在"能跑"的帧上宣布完成** | 能跑 ≠ 好看。必须走 §2 的第 ④~⑥ 步 |
| **拿自己上一版当参照** | 只说明"比上次好"，不说明"够专业"。参照必须来自**外部专业作品** |
