# 启动体验：窗口创建 / 磨砂启动卡（2026-11-08 落地记录）

> 前因（调研）：`docs/STARTUP_UX_STUDY_20261108.md`。本文记录**实际做了什么、量到什么、踩到什么坑**。
> 口径：Windows 11 build 26200 / RTX 4080 SUPER / 3533×1921@1.5 / dev 档 / `gallery`（最重的那类应用）。

---

## 一、结论（一页）

| 项 | 结果 |
|---|---|
| 启动底色硬编码亮色（暗色主题白闪） | **已修**：`Backend::set_window_background`，跟随主题 |
| 启动期"一块静止底色 ~380ms" | **已消除**：换成一张**磨砂玻璃启动卡**（品牌标记 + 脉冲环 + 扫光） |
| 磨砂技术路线 | `SetWindowCompositionAttribute(ACRYLICBLURBEHIND)` + `WS_EX_LAYERED` + `UpdateLayeredWindow` |
| 启动卡代价 | **净增 ~22ms**（绘制 6.6ms + 上屏 19ms）；总启动 422ms → 445ms |
| 时序正确性 | 首次绘制前**暂停 GPU 换型**（否则第 12 帧起卡消失，见 §3.3） |
| 回归 | `tests/app_splash_test.cpp` 4 条；`tools/splash_probe.cpp` 三条断言；全量测试通过 |

**关键取舍（诚实记录）**：启动卡**不是**"填满原本就在等的时间"，而是**净增 22ms**。
原因是首帧那 373ms 与后台 GPU 预热（390ms）本来可以并行，而任何在主线程上跑的东西
都会把它们排到后面（实测：动画跑 341ms ⇒ 总启动 748ms，正是 455+341）。

所以落地形态选了**一帧静态卡**（< 26ms），而不是动画循环。真正的"动画无代价"需要先把
首帧拆成可中断的分段（调研稿 §4-D），那是另一件事。

## 二、磨砂：三条路线的实测对比（这是本轮的硬结论）

在**霜天自己的窗口形态**（`WS_POPUP` + `WM_NCCALCSIZE` 归零 + 自绘窗框）上逐个试：

| 通路 | 背景模糊 | 应用自己画的内容 | 结论 |
|---|---|---|---|
| `DWMWA_SYSTEMBACKDROP_TYPE = Mica` | 只有桌面壁纸 | — | **不可用**：看不见窗口身后的内容 |
| `DWMWA_SYSTEMBACKDROP_TYPE = Acrylic`（Transient） | **有真模糊**（一行 219 个过渡色值） | **被完全盖掉**（屏幕采样一片 211,211,211） | 不可用 |
| `SetWindowCompositionAttribute(ACRYLICBLURBEHIND)` | **有真模糊** | **被完全盖掉** | 单独不可用 |
| **上面两者任一 + `WS_EX_LAYERED` + `UpdateLayeredWindow`** | **有真模糊** | **正常合成**（层上 alpha=0 透背景、alpha=255 显示内容） | ✅ **采用** |

> 两条"被盖掉"的共性：一旦给窗口开磨砂（并 `DwmExtendFrameIntoClientArea(-1)`），
> 客户区变成"玻璃"，**GDI 往窗口 DC 上 `BitBlt` 的像素不参与合成**。
> 而 `UpdateLayeredWindow` 是应用把**每个像素的 alpha** 交给合成器的公开通路，两者能共存。
>
> 复现脚本：`tmp/backdrop_probe3.py`（档位对比）、`tmp/backdrop_probe4.py`（GDI 通道）、
> `tmp/backdrop_probe5.py`（分层通道）、`tmp/backdrop_probe6.py`（尺寸/时序）。
> 这些是**一次性量尺**（按 `CONVENTIONS §8` 不进产物），结论已固化进
> `Win32Backend::set_backdrop_blur` 的注释与本文。

### 2.1 分层上屏的两条硬约束（都踩过）

1. **`rotate_bgra_row` 不能用**：它是给 GDI `BitBlt` 写的，末尾 `| 0xFF000000U`
   把 alpha 强制成不透明（GDI 不认 alpha，必须全不透明）。
   而 ULW 要的正是真实 alpha —— 用它就是"整窗被当成 100% 不透明"，
   屏幕上一片纯色，**而 `UpdateLayeredWindow` 返回成功**。
   正解：`dst = (src >> 8) | ((src & 0xFF) << 24)`（保留 alpha 的循环移位）。

2. **磨砂必须在 `ShowWindow` 之前开**：先显普通窗口再转分层，Windows 会把显窗那帧的
   重定向表面当成初始图层，后续 ULW 的逐像素 alpha 被当成整窗一个 alpha。
   顺序：`SetLayered + 磨砂` → `ShowWindow` → `ULW 送内容`。

## 三、启动卡本身

### 3.1 三层合成

| 层 | 画什么 | 要点 |
|---|---|---|
| ① 底 | 磨砂档：`clear` 成 alpha=0；无磨砂档：填主题底色 | alpha=0 才能透出合成器的模糊 |
| ② 玻璃卡 | **白色**低 alpha（0.17）垂直渐变 + 1.5px 强调色内描边 | **不能用主题底色**——深色主题下与背景同值，卡彻底看不见（实测中心像素 (7,7,9) 与背景同值）。预览图里正常是因为那里叠的是亮背景，典型的假阳性 |
| ③ 动效 | 三层交错脉冲环（各错开 1/3 周期）+ 菱形品牌标记 + 横向扫光带 | 全部解析式渐进，无状态机 |

### 3.2 三条观感参数（都是实测定下来的）

- **卡片不透明度 0.17**：0.10 时暗背景上看不见，0.30 时盖掉磨砂纹理。
- **脉冲周期 1.15s**：<0.6s 显得焦虑，>2.5s 读成卡死。
- **柔光晕 8 层**：三层能看出三道台阶（单层 alpha 跳变 ~3/255，磨砂背景很平，阶跃显眼）；
  8 层时降到 ~1/255，8 位通道上不可分辨。代价 < 1ms。

### 3.3 踩过的四个真缺陷（都在真窗口上才暴露）

1. **GPU 换型把画布换走**：`framebuffer()` 里会 `try_upgrade_to_gpu()`。GPU 预热 390ms 就绪后
   画布变成 GPU 画布，而启动卡只能画在 `raster::Canvas` 上 ⇒ 第 12 帧起卡不再绘制，
   屏上只剩磨砂底。**帧数与日志全都正常**，靠逐帧打印 DIB 像素才查到。
   修：新增 `Backend::pause_deferred_upgrade(bool)`，动画期暂停换型。
2. **`fill_rect` + `BlendMode::Src` 不能把像素清成全零**（对 a=0 有早退语义）。
   要清零只能 `clear` 或直接写像素。
3. **光晕外溢**：三层等权时最外圈在窗口四角仍有 18/255（7%）的雾，磨砂纹理上看得出来。
   修：二次衰减 + 8 层（外圈降到 ~1/255）。
4. **测试画布失真**：用 320×220（卡宽 320 就撑满窗口）时四角测到 18~20——
   那是**测试画布太小**，不是实现问题（1280×800 下同样参数四角是 0）。
   修：测试改用真实比例 1280×800。

### 3.4 绘制与上屏的代价（用 `ST_SPLASH_DEBUG=1` 分段量）

优化前后（3533×1921 @1.5）：

| 分段 | 优化前 | 优化后 | 手法 |
|---|---|---|---|
| 柔光晕 | **17.3ms** | 0.9ms | 径向渐变（逐像素 `sqrt`）→ 8 层圆角矩形纯色填充 |
| 扫光 | **6.2ms** | 0.2ms | 逐列 138 次 `fill_rect` → 一次横向渐变 |
| 脉冲环 | 2.2ms | 2.2ms | 三条 donut 路径，不动 |
| 其余 | ~1ms | ~1ms | — |
| **绘制合计** | **26.9ms** | **6.6ms** | — |
| **上屏（ULW）** | 19.0ms | 19.0ms | 整窗 27MB 拷贝，分层通道固有 |

### 3.5 观感对照产物

- `build/splash/splash-preview-t*.png`：卡合成到**模拟的真实暗色磨砂背景**上的预览
  （注意：预览背景必须取实测值 6~27，早期用亮蓝底预览时"卡在暗背景看不见"这个缺陷完全被掩盖）。
- `build/splash/splash-blur-t*.png` / `splash-solid-t*.png`：裸帧（磨砂档 / 无磨砂档）。

## 四、开关与控制通道

| 开关 | 作用 |
|---|---|
| `AppOptions::splash`（默认 true）/ `--no-splash` | 开关启动卡（截图/基准要确定性首帧时关掉） |
| `AppOptions::splash_backdrop_blur`（默认 true） | 磨砂档；关掉或无合成器时退化为"主题底 + 近不透明卡" |
| `AppOptions::splash_style`（`SplashStyle`） | 卡片宽/半径/不透明度/光晕/环半径/周期/帧率 |
| `ST_SPLASH_MS=N` | **演示/录屏用**：把启动卡变成跑 N 毫秒的动画（默认只画一帧）。⚠ 会净增启动耗时 |
| `ST_SPLASH_DEBUG=1` | 输出分段计时与 DIB 像素诊断（排障用） |

## 五、还没做的（诚实清单）

1. **动画"无代价"**：需要把首帧拆成可中断分段（字体预热 / 排版 / 绘制 / 建表），
   把动效插在段与段之间。这是本轮明确**没做**的那件事，也是启动卡目前"净增 22ms"的根因。
2. **`show_early` 的跨平台缺口**：仍只有 win32 实现（x11/wayland 是"首帧画完才映射"）。
   启动卡同理——`set_backdrop_blur` / `refresh_early` 在非 win32 后端是空实现，
   所以那两个平台**不会**出现启动卡（不是坏了，是没接）。
3. **建窗一次到位**（画布分配 3 次 → 1 次）：调研稿 §2.2 记的那个优化点，本轮没动。
4. **启动打点缺口**：`log_startup_summary()` 只有 gallery 自己补调了；
   相期/裁云/gbcode 用自建主循环，启动成本仍是黑箱。
