# 裁云能力台账（Capability Ledger）

> **这份文件解决什么**：回答"裁云现在能做什么、不能做什么、下一步该补什么"。
> 每次做片撞到的缺口都要登记在这里，**不要只留在对话里**。
>
> **为何单独立一份**：实测（2026-10-22）做"图标落桌面"那条片时，为了做出
> "跳起来→站稳"，被迫连续补了 5 项能力（UV/纹理、多网格共享世界、弹跳、
> 接触阴影、程序化桌面）。这些缺口**做片之前完全不知道存在**——
> 而每一条都是可以提前补的通用能力。

## 二、缺口优先级（按"做片时被卡住的次数"排序）

> **2026-10-23 清账**：原先的 P0（路径动画）、P1（关键帧）、P2（squash）已全部落地，
> 不再列在本章（已做项归 git 提交说明）。下面只留**仍未做**的缺口。

### P1·理想建议会对"语义错"无能力（已部分弥补）

**现状**：`schema.hpp` 的别名表能盖住常见同义写法（`model_rot`→`model_spin`），
但**未登记的同义词**仍会落到编辑距离上，可能推荐个语义不对的字段。
补法：遇到新的写错案例就往 `Aliases()` 里加一条（成本低、可累积）。

**另：诊断已完备，但缺"强制与回传"两个环节**（2026-10-27 补）

现有的诊断能力已经覆盖：未知字段 + 编辑距离建议 + 同义词别名 + 越界报实际生效值
（`schema.cpp` 的 `unknown_key_diagnostic` / `suggest_field` / `out_of_range_diagnostic`）。
**但静默失败仍会发生**，因为：

1. 有诊断**也照常渲染**（无 `--strict`，退出码 0）——工具与 CI 拿不到“失败了”；
2. 诊断要**另发一次 `get director schema_diagnostics`** 才看得到，不是一个回合内就回答的；
3. 字段表**导不出标准 JSON Schema**，因此无法喂给约束解码（让错误字段名在生成时写不出来）。

方向：① 加 `--strict`（`diagnostic_count > 0` ⇒ 不出片、非 0 退出）；
② `apply_script` 直接回诊断；③ 从 `FieldSpec[]` 生成 draft-2020-12 JSON Schema。

### P2·场景/图层级「跨字段约束」未校验

**现状**：单字段的范围已查，但字段之间的约束没有，例如：
- `model_group` 非空时，`cam_*` / `light_*` **只有组首生效**（写了不生效但无提示）；
- `path_to_x` 为空时，`path_arc` / `path_dur` 全部无效；
- `model_shadow` 在**非组**图层上不生效（需要地面，单图层没有世界）。

这些是“写了没反应”且**当前诊断不会报**的一类。方向：在 `parse_layers` 末尾
加一个跨字段检查遍，复用同一份 `Diagnostic` 通道。

### P3·AO / 真阴影

接触阴影现在靠二维椭圆近似——相机固定时够用，**换机位就露馅**（影子不随透视变形）。
要真做需要阴影贴图（GPU Gems Ch.11：深度图 + bias + PCF）。

### P4·运镜

有 `cam_dolly`（沿视线推拉）但**没有 orbit**（绕物体转）。产品视频最常用的就是 orbit。

## 三、流程缺口（比能力缺口更贵）

### 3.1 观感类改动必须有量化判据

**实测代价**：做三维片子时，前三版都被判"粗糙"，而**我没有任何量尺**，
只能凭感觉加东西。补上量尺之后立刻定位到两个真问题：
色相数 10→1（廉价感）、接触暗度 0→157（贴纸感）。

详见 `docs/visual_craft.md`。

### 3.2 一项能力一项验证，不要捆在一起

**实测代价**：我把 UV、纹理、共享世界、弹跳、阴影、配色**六个改动捆在一轮**，
失败时完全无法归因，最后花了十几轮才逐个排除。

### 3.3 "改坏了要能一键回到已知好状态"

**实测代价**：v7（可用）→ v8/v9/v10（逐次更差），因为我没有提交检查点，
只能靠 `out/v7w/` 的截图确认"曾经好过"。
**应当**：每达到一个可用状态就 `git commit`，改坏了 `git checkout`。

### 3.4 子代理提示词要写"能力边界"

现在 `caiyun.ts` 里写了三维**能**做什么，但没写**不能**做什么
（无路径动画、无阴影贴图、无 AO）。子代理会写出做不到的剧本。
