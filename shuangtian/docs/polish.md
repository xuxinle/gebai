# 精致度：指标测不到的那一半

> 来源：2026-10-24 用户反馈「大方向没问题，细节不够精致，指标应该度量不了」。
>
> 这句话是对的。现有评测只量**运动量**（静止占比 / 变化中位数 / p95）
> 与**亮度**，它回答"有没有在动、有没有发白"，**回答不了"好不好看"**。
> 13 个 case 全绿，抽帧仍有五处一眼可辨的廉价感。

## 一、三类"不精致"（都有抽帧证据）

### ① 纯色几何体，没有材质层次

| case | 抽帧看到的 |
|---|---|
| infra | 所有"丝"是**同一根直线随机旋转**——同长、同粗、只有角度不同，像撒了一把牙签；中心是 3 个纯色圆硬叠，**看得见三道色阶** |
| domino | 手机是纯色矩形，一糊就成噪点 |
| clearing | 日历块只有底色 + 两条灰线当"文字" |
| **clawd（反例）** | 窗口有投影、圆角、交通灯、毛玻璃，背景棋盘有透视 —— **明显高一个档次** |

差别不在"动了多少"，而在**同一块面积上有几层信息**。

### ② 运动模糊压掉了识别性

domino 抽帧整屏拖影，手机边缘糊成雾。模糊本该表达速度，
实际把"这是什么"抹掉了。`--motion-blur 4` 对快速 3D 场景太重。

### ③ 靠"放大"制造运动，放大到最后只剩抽象色块

clearing 把日历格放到满屏，观众看到的是蓝块 + 灰线，读不出"这是日历"。

## 二、四个手法（成本从低到高）

### 手法 1：每根"丝/线"用**多段 + 粗细渐变 + 透明度衰减**

```js
const SEG = 5;
let cx = x0, cy = y0, cwid = lw, calpha = a;
for (let k = 0; k < SEG; k++) {
  const u = (k + 1) / SEG;
  const ang = Math.sin(ph + u * 2.6) * 0.55;      // 方向随高度摆 → 自然弯曲
  const segLen = (len / SEG) * (1 - u * 0.25);
  const nx = cx + Math.sin(ang) * segLen;
  const ny = cy - Math.cos(ang) * segLen;
  shapes.push({ kind: 2, x: cx, y: cy, x2: nx, y2: ny,
                stroke: cwid, color: "#FFF4DB", alpha: calpha });
  cx = nx; cy = ny;
  cwid *= 0.80;      // 每段收细 20%
  calpha *= 0.86;    // 每段变淡 → 末端自然消散，不出现硬截断
}
```

**关键**：粗细与透明度**同时**递减。只减一个会出现"细但很实"或"淡但很粗"的假象。

### 手法 2：光源用**多层渐进叠加**，不要 3 层

```js
// 错：3 个圆 + 0.95/0.30/0.12 → 三道硬边色阶，像三个同心圆
// 对：8 层等比（半径 ×1.32、alpha ×0.62）→ 叠加成平滑径向衰减
for (let g = 0; g < 8; g++) {
  const rr = coreW * Math.pow(1.32, g);
  const aa = 0.92 * Math.pow(0.62, g) * fadeIn;
  if (aa < 0.012) break;
  shapes.push({ kind: 0, x: fx, y: fy, w: rr, color: heatColor(1.0 - g * 0.028), alpha: aa });
}
```

外层色温略低（向白偏）更接近真实热辐射。

### 手法 3：图元加渐变/描边，不要纯色

裁云的图元支持 `fill_alt`（渐变）+ `stroke`。**一个上亮下暗的矩形**
与一个纯色矩形，在屏幕上差的是"卡片"与"色块"。

### 手法 4：运动模糊按速度自适应

快镜头用 2、慢镜头用 4~6。全片同一个值必然有一端是错的。

## 三、判据：抽帧看这三件事

指标不管用，所以必须**看图**。逐帧放大后问：

1. **同色区域里有没有层次？**（纯色 → 加渐变/描边/多层叠）
2. **形状还认得出来吗？**（糊/放大到抽象 → 降模糊倍率、收推镜上限）
3. **这一帧有几种"材质"？**（全是平涂 → 加阴影/高光/透明度分层）

## 四、为什么这不能用指标补

变化强度量的是**格均值的差**：一个纯色圆和一个有渐变+高光的圆，
在"动起来"时给出的差值可能完全一样（都是占同样面积的色块在移动）。
指标只能区分「动不动」，不能区分「像不像」。

所以两类检查必须并存：

| 检查 | 工具 | 管什么 |
|---|---|---|
| 运动量 | `ot_bench.py` | 有没有在动 / 过亮 / 单调 |
| **精致度** | **抽帧 + 人眼** | **材质层次 / 形状识别 / 材质种类** |

后者**无法自动化到可判定**，只能缩小要看的范围（一次看 6 帧而不是 400 帧）。
