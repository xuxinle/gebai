# 剧本设计模板（裁云 / 镂月通用）

> **这份文件先于脚本存在。** 脚本是剧本的执行，不是剧本本身。
> 顺序：**剧本 → 确认 → 脚本 → 出片**。跳过剧本直接写脚本，返工代价最大
> （改一句话要重渲全片，而剧本阶段改一句话是零成本）。

## 第一部分：定位（先想清楚给谁看）

| 项 | 内容 |
|---|---|
| **一句话定位** | 给____看，看完记住____（不是功能罗列） |
| **受众** | 谁会看？他们关心什么？ |
| **使用场景** | 官网首屏 / 发布会大屏 / 社交投放 / 内部汇报 |
| **时长与画幅** | 目标时长 ___ 秒；16:9 / 1:1 / 9:16 |
| **语言与声音** | 中文/英文；有无配音；**音效（默认无）** |

## 第二部分：内容结构（能量曲线）

按**叙事**而不是按功能列表排。每段写清三件事：**这段要让观众产生什么反应**、
**画面里出现什么**、**停留多久**。

| 段 | 作用 | 观众反应 | 时长 | 画面主体 |
|---|---|---|---|---|
| 1 开场 | 建立注意 | "这是什么？" | 2~3s | ____ |
| 2 立传 | 说清是什么 | "哦，是干这个的" | 2~3s | ____ |
| 3 展开 | 给证据 | "具体怎么做" | 2~3s | ____ |
| 4 峰值 | 印象最深的一点 | "有意思" | 2~3s | ____ |
| 5 收尾 | 留下记忆点 | 记住名字/一句话 | 2~3s | ____ |

**能量走向**：低开 → 单主角立传 → 爬升（高低交替）→ 峰值收场。
**节奏单向偏好**：历史反馈全部指向「放慢/停留」，从未有人说「太慢了」。
所以每个关键元素落定后留 **≥1s 静止**，宁慢勿急。

## 第三部分：逐镜设计（这是剧本的主体）

每个镜头一行，写清五件事。**这一节写完，脚本几乎是抄下来的**。

| # | 时长 | 画面构成（谁在哪、多大） | 文字（逐字） | 动效（入场/持续/落定） | 转场 |
|---|---|---|---|---|---|
| 1 | 2.4s | 居中大字 + 背景光晕 | 标题「___」/ 副标「___」 | 上浮淡入 → 静止 1.2s | 交叉淡入 0.3s |
| 2 | 2.6s | 左侧图片卡 + 右侧三行 | 「___」「___」「___」 | 图片缩放落定 / 文字逐行错峰 0.15s | 光扫擦除 |
| 3 | … | … | … | … | … |

**写法约束**（这些是踩过坑的）：

- **一镜只讲一件事**。同一镜里两个重点 = 观众记住零个。
- **文字逐字写出来**，不要写"类似上面的文案"——文案是设计的一部分，不是填空。
- **每镜标出采样帧**（入场中 / 动作峰值 / 落定后三个时间点），
  后面自检就按这三个点抽帧。
- **动效幅度写具体**：不说"轻微推镜"，说"从 1.0 推到 1.06"。

## 第四部分：视觉规范（从产品自身生长）

**不要另造"宣传片皮肤"**。从产品自身的界面/文档/设计系统里取：

| 项 | 值 | 来源 |
|---|---|---|
| 强调色 | `#______` | 产品的主按钮 / Logo / 主题变量 |
| 背景色 | `#______` → `#______` | 产品的深色主题 |
| 字体与字重 | ____ | 产品用的字族 |
| 字号层级 | 主标题 ___ / 副标 ___ / 正文 ___ | 与产品 UI 同比例 |
| 圆角与间距 | ___ | 产品组件的圆角 |
| 影像特效强度 | glow ___ / particles ___ / dof ___ | 见下方"特效克制表" |

**特效克制表**（超出这个范围会变廉价）：

| 参数 | 舒适区 | 说明 |
|---|---|---|
| `glow` | 0.4~0.9 | 舞台光晕；拉满变成科幻片 |
| `particles` | 40~90 | 浮尘；再多像雪花屏 |
| `dof` | 0.2~0.5 | 景深；过大背景糊成色块 |
| `cam_zoom` | 1.0 → 1.08 | 推镜；**不超过 1.08**（安全边距只有 5%） |
| `cam_rotate` | ≤0.8° | 旋转；超过 2° 让人晕 |

## 第五部分：声音设计

**默认策略：配乐 + 配音，零音效。**

| 时点 | 类型 | 内容 | 时长 |
|---|---|---|---|
| 0.0s | 配乐 | 曲风 uplift / calm，BPM ___ | 全程 |
| ___s | 配音 | 「___」 | 实测后回填 |
| （空） | 音效 | **不加；若要加，逐条写「为什么必须加」** | — |

**顺序**：配音先定稿（实测时长）→ 回头重排镜头窗口。
**画面等解说的长度，不是解说追着画面跑。**

### 音效：为什么默认不加

裁云把 `audio.voice` 里所有轨一视同仁地混音，**只对配乐做 ducking（压到 35%），
对音效不做**——于是音效与旁白直接抢响度。实测一条 `success` 音效
峰值 −5.7dB / 均值 −17.5dB，比同时刻旁白**还响 2.5dB**，听感上就是「叮一下把说话盖掉」。

`tts_sfx` 的预设定（success / ding / sparkle / riser / impact / whoosh）都是正弦与噪声合成，
**音色偏电子玩具感**，与冷静的技术叙事不同频；`riser→impact→sparkle` 三件套
是预告片套路，用在没有爆点的产品片上等于给不存在的爆点造势。

### 什么时候才加（满足任一条，且写进剧本写明理由）

- 有明确物理动作需要声音背书（切镜、砸下、打字、开盒），且**该处无人声**；
- 用户明确要求「要有音效 / 要有声势」；
- 片子无旁白（纯音乐片），可用音效做节奏点。

### 加的时候的三条硬约束

1. `gain` ≤ 0.25（默认 1.0 会把旁白盖掉），且必须实测该点 `volumedetect` 均值
   **低于同时刻旁白至少 6dB**，不达标就降 gain 或删掉；
2. 音效只钉在**旁白的空隙**（旁白前后各留 ≥0.2s），不在说话中间插；
3. 全片音效 ≤ 3 处，且不要每个转场都 whoosh（同一技法重复 = 噪点）。

## 第六部分：确认点

| 确认点 | 送审内容 | 通过标准 |
|---|---|---|
| C1 概要 | 本文第一~四部分 + 一张静帧 | 定位/结构/视觉方向无异议 |
| C2 每节主帧 | 每节最能代表构图的 1 帧 | 该节版式与文案无异议 |
| C3 成片 | 成片 + 每节抽 1 帧 + 偏离清单 | 放行交付 |

**禁止几节做完一次性送审**——反馈越晚越贵。

## 附录：把剧本翻译成脚本

剧本第三部分的一行 ≈ 脚本里一个场景。对照：

| 剧本 | 脚本字段 |
|---|---|
| 时长 | `duration` |
| 画面构成（内置版式） | `kind: title / terminal / triptych / metrics / outro` |
| 画面构成（自由版式） | `kind: custom` + `layers: [...]` |
| 文字 | `title` / `subtitle` / `lines` / `values`，或图层 `text` |
| 动效 | 场景特效 `glow`/`particles`/`dof`/`cam_*`，或图层 `enter` |
| 转场 | 顶层 `transition` |
| 声音 | `audio.voice[]` / `audio.bpm` / `audio.style` |

**自由版式（`kind: custom`）能做的事**：任意数量的矩形/椭圆/线/文字/图片/路径/光晕/粒子/**三维模型**，
用 `x/y/w/h` 定位（设计像素或 `"50%"` 比例），`enter` 控制入场动画。
**绝大多数"想做但内置版式没有"的画面，都能用 custom + layers 拼出来——不需要改 C++。**

## 附录 B：三维图层（`kind: model3d`）

把真实三维几何画进一块矩形。背后是框架的 `raster::Scene3D`，**有显卡走显卡、
无显卡自动降级到软件光栅器**，脚本不用改一个字。

```json
{"kind":"model3d","x":"26%","y":"8%","w":"48%","h":"84%",
 "model_shape":"box","model_color":"#8fbcff","model_color_alt":"#2b4d8f",
 "model_spin":13,"model_yaw":-18,"model_tilt":16,
 "cam_azimuth":32,"cam_elevation":20,"cam_distance":3.1,"cam_fov":36,
 "light_azimuth":38,"light_elevation":52,"light_ambient":0.32,"light_rim":0.42}
```

### 字段

| 字段 | 默认 | 说明 |
|---|---|---|
| `model_shape` | `box` | `box` / `sphere` / `torus` / `cylinder` / `plane` / `obj:<路径>` |
| `model_color` / `model_color_alt` | 蓝 / 透明 | 主色与次色（次色非透明时按竖直方向双色渐变）|
| `model_segments` | 24 | 细分（球/环/柱）；24 在 720p 已看不出棱，48 用于特写 |
| `model_scale` | 1.0 | 模型相对图层矩形的缩放 |
| `model_spin` | 0 | **自转角速度**（度/秒，绕 Y）。用速度而非总角度：片长改了转速不变 |
| `model_yaw` | 0 | 初始角度（度）：让同一模型在不同镜头里朝向不同 |
| `model_tilt` | 12 | 绕 X 固定倾斜（度）：产品展示常用 10~20° 显立体 |
| `model_bob` / `model_bob_hz` | 0 / 0.35 | 上下浮动幅度与频率（幅度 0.03~0.08 是舒适区）|
| `cam_azimuth` / `cam_elevation` | 35 / 18 | 相机球坐标（度）：0 = 正前方，仰角正 = 俯视 |
| `cam_distance` | 3.0 | 相机到模型距离（模型单位 1，建议 2.2~4.0）|
| `cam_fov` | 38 | 视野角：小 = 长焦压缩（更像产品摄影），大 = 广角变形 |
| `cam_dolly_from` / `cam_dolly_to` | 1.0 / 1.0 | 整段推拉的**倍率**：1.0 → 1.06 就是「推 6%」|
| `light_azimuth` / `light_elevation` | 40 / 45 | 主光方向（度）|
| `light_ambient` | 0.35 | 环境光：0 = 背光面全黑，0.35 = 柔和底光 |
| `light_rim` | 0.25 | 边缘光：让模型从背景里浮出来（0.35~0.5 很出彩）|
| `model_backdrop` | false | true = 用主色铺满矩形；false = 带透明通道，可叠在视频背景上 |
| `model_texture` | 空 | 纹理源（PNG/SVG）；**仅 `textured_*` 形状带 UV** |
| `model_group` | 空 | 场景组名：同名图层共用一个三维世界（同一相机/光照/正确遮挡）|
| `model_shadow` | 0 | 接触阴影强度（**仅组内生效**，0.45~0.65 建议）|
| `model_shadow_color` | 近黑 | 阴影颜色（带一点环境色比纯黑自然）|
| `model_bounce_squash` | 0 | 形变强度（体积守恒的 squash & stretch，0.10~0.20）|

### 三条纪律

1. **矩形给足留白**：模型按相机视锥自适应，约占矩形 62%。矩形太小会让模型
   显得拘束；`x` 与 `w` 相加不要超 100%。
2. **自转宁慢勿快**：8~15 度/秒是“缓慢自转”，20 以上变成“陀螺”，30 以上让人晕。
3. **光照就是构图**：正面平光（azimuth 0）读起来平；侧逆光（azimuth 120~150 +
   rim 0.45）才有体积感。默认值（40/45）是安全的正面偏侧光。

### 跨场承接（`carry_out`）—— 不做它就是幻灯片

**分镜之间没有东西活下来，就是把上一幕替掉**。每一镜单看再好，合起来还是翻页。
这是成熟动效片判定“像 PPT”的准确形态，也是它们**唯一能自动验收**的一项。

在场景上加 `carry_out`，声明一个**跨边界**的图元：

```jsonc
"carry_out": {
  "name": "承接·生长",     // 必填：验收器靠它认身份
  "into": 1,               // 交给哪一幕
  "at": 4.65,              // 变形起点（**成片时间**，不是幕内时间）
  "dur": 0.70,
  "from": { "x": "32%", "y": "32%", "w": "36%", "h": "36%", "radius": 16 },
  "to":   { "x": "0%",  "y": "0%",  "w": "100%", "h": "100%", "radius": 0 },
  "fill": "#152238", "stroke": "#4d6bfe", "stroke_width": 3,
  "text": "一镜到底", "text_color": "#9ec4ff", "text_size": 44,
  "curve": "expo_out",
  "fade_out": 0.45         // 末段淡出，让位给下一幕内容
}
```

**三条硬约束**（都踩过）：

| 约束 | 原因 |
|---|---|
| `at < 边界 < at+dur` | 变形在边界前结束 ⇒ 两侧没有共同物体 ⇒ 只拿一半分 |
| 不许整屏不透明地盖上去 | 承接在合成**之上**；整屏不透明 = 遮罩，实测把整幕文字盖没了 |
| 铺满阶段用 `fade_out` 让位 | 否则卡片长满到文字出现之间是 0.4s 空屏（实测第 160 帧全空） |

验收：`python scripts/carry_qa.py <输出目录>/trajectory.tsv --scenes <各幕时长>`。
完整方法（判据/基准/坑）见 `docs/caiyun_carry.md`。

### 不确定字段时：直接问应用（不要猜）

字段名/类型/范围选择**以应用的自省面为准**，不要靠记忆：

```jsonc
// 全部可写字段（含类型/范围/默认/一句说明）
{ "method": "get", "params": { "id": "director", "property": "schema_json" } }

// 上一次脚本解析产生的诊断（未知字段/越界/不支持的关键帧属性）
{ "method": "get", "params": { "id": "director", "property": "schema_diagnostics" } }
```

写错字段名不会静默通过：`schema_diagnostics` 会给出
`{"path":"scenes[0].layers[1]","key":"model_rot","suggestion":"model_spin"}`
这类带**建议名**的记录。**改完先读它，再看画面**。

### 诚实边界（这些做不到，不要写进剧本）

- **没有 PBR / 法线贴图 / 反射 / 环境贴图**：光照是 Lambert + 环境 + 边缘光三项。
- **近似阴影**：接触阴影是**二维椭圆**（贴在图层底部），不是阴影贴图；
  相机固定时够用，**换机位就露馅**（影子不随透视变形）。且**只在 `model_group` 内生效**
  （需要知道地面在哪）。
- **没有环境光遮蔽（AO）**：缝隙不会变暗，密集物体互相接触处的体积感偏平。
- **没有三维文字**：文字仍由渲染器画二维（清晰可读），不跟随模型透视。
- **OBJ 只取几何**：材质库（`mtllib`/`usemtl`）与纹理坐标一律跳过，模型用 `model_color` 平涂。
- **贴图只对 `textured_*` 形状生效**：`textured_box` / `textured_plane` / `textured_slab`
  带 UV；`box`/`sphere`/`torus`/`cylinder` 是无 UV 的纯色网格。
- **组内只有一个相机、一盏主光**：取**组首**图层的 `cam_*` / `light_*`，成员的这两个字段被忽略。

### 性能（实测，1080p × 390 帧）

| 场景 | 每帧渲染耗时 |
|---|---|
| 三维图层 + 文字 + 特效（本机无 GPU 直通时走软件腿）| **178 ms** |
| 同上但强制走 GPU 腿（结果要回读给软件画布）| **2234 ms** |

**后者慢 12 倍**——因为软件画布接不住显存里的纹理，每帧要回读一次；而导出是
16 路并行，回读要同步等 GPU，线程全在锁上排队。所以裁云现在**按目标能力选腿**：
目标接不住纹理时主动用软件腿。你不需要关心这件事，它已自动处理；
但**如果你在别处自己调 `Scene3D`，记住这条**：显卡只在纹理能留在显存里时才值。
