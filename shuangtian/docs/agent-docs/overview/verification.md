# 验收：收单前该验什么

## 一单交付的最小证据集

| 交付类型 | 必须有的证据 |
|---|---|
| **改了界面外观** | `capture` 截图（肉眼可判）+ `visual_diff` 与基线比对（差异量在容差内或变动已解释） |
| **改了行为/交互** | `tree`/`get` 属性面断言（值真的变了）+ `invoke` 或 `click` 触发的 `handled` |
| **修了缺陷** | **回归测试** + **逆向验证**（把修复临时回退，断言必须变红） |
| **新增框架能力** | 用例（含"默认值不变"那条）+ 文档同步 + lint/全量测试绿 |
| **改了观感（字体/配色/动画）** | 用户可判的截图 + 量化口径（总墨量比/统计量）+ 默认档抽成常量供测试引用 |

## 像素断言的两个原语

- `capture_hash`：判"变了没有"（快）。
- `visual_diff`：与基线逐像素比对，给差异量。首次 `write_baseline=true` 存基线；
  `tolerance` 吸收抗锯齿抖动（如 0.001），`threshold` 不计入差异像素。
- 回归循环：改代码 → build → 重启 → `visual_diff` → 超限才看截图人工定位。

## 逆向验证（不做这一步就等于没测）

把修复**临时回退**，确认测试真的变红，再恢复。三个高危变体（都实际发生过）：

| 变体 | 症状 | 处置 |
|---|---|---|
| **桩把差异抹平** | 被测的是"谁把值传给谁"，桩回了个恒等值 ⇒ 错误实现也判绿 | 桩必须复现被测的那一段真实行为（该夹取就夹取） |
| **回退版编译不过** | `-Werror` 打断编译 ⇒ 跑的是上一份二进制 ⇒ 假绿 | 回退写法要能编译过（保留 `(void)var;`） |
| **恢复用 `copy2`** | 把旧 mtime 搬回来，比回退版 `.o` 还旧 | 删旧文件再写 |

## 判据自己也会错

下结论之前先问：**我量的是行为、是代码，还是只是一个字符串？**

- "N 轮全绿 ⇒ 没问题"是**分辨力的误读**：N 轮全绿只说明失败率 p ≲ 3/N。
  报零红必须同时给：轮数 + 对照条件（负载/并发/形态）+ 该条件下的检出下限。
- **看不到问题先怀疑观测手段**：`capture` 截的是应用内部画布（恒定正确）；屏幕上的实际像素可能不同
  （启动瞬态、窗口映射时序）。要查"窗口上真是什么样"，得从桌面 DC 直接抓——但注意
  `PrintWindow` 会**触发一次重绘**、把要观察的瞬态修好。
- **采样粒度要细于被测特征**：抓取本身耗时（全窗口一次可能十几毫秒），稀疏采样会把
  "瞬时问题"测成"持续 60ms"。

## 「绿而无效」的形态识别

| 形态 | 一句话 |
|---|---|
| 零红没报分辨力 | 窗口太小，结论没被真正检验 |
| 回退是空操作 | 回退没改到东西（如 `if (len < 0)` 恒假） |
| 回退版编译不过 | 根本没跑到新代码 |
| 锚点会过期 | 锚点描述的是已死的缺陷，留着等于逼人把 bug 写回去 |
| 锚点只在注释里 | 只证明"字符串还在"，不证明"那行代码还在" |
