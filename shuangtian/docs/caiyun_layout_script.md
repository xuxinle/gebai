# 裁云 · 脚本编排层（layout.js）

> **一句话**：JSON 声明"有什么"，JS 声明"每一帧变成什么样"。
> 没写 `layout` 时行为与纯 JSON **一字不差**。

---

## 1. 何时用它

| 场景 | 用 JSON | 用 JS |
|---|---|---|
| 单个物体从一个位置飞到另一个位置 | ✅ `path_*` 够了 | — |
| **20 个图标错峰入场** | ❌ 要写 20 遍 | ✅ 一个 `for` |
| **位置随某个自定义曲线变化** | ❌ 得加字段 | ✅ 写数学式 |
| **按条件决定做几幕/几个元素** | ❌ 表达不了 | ✅ `if` |
| **互相牵引的运动（A 跟随 B）** | ❌ 无状态机 | ✅ 循环里算 |
| 静态版式、简单淡入 | ✅ | — |

**判据**：如果你发现自己在"为一种新动作加一个新字段"，就该用 JS。

---

## 2. 写法

在场景里加 `layout` 字段：

```jsonc
{
  "scenes": [{
    "kind": "custom",
    "layers": [ /* JSON 照常声明图层 */ ],
    "layout": "layout.js"          // 相对本 JSON 文件
  }]
}
```

也可以内联（适合短脚本）：

```jsonc
"layout": { "source": "function layout(t){...}", "timeout_ms": 400 }
```

`layout.js` 里**必须**定义一个全局函数 `layout`：

```js
function layout(t, duration, canvas, layers) {
  // t        当前时间（秒，场景内相对时间）
  // duration 本幕总时长（秒）
  // canvas   { width, height }（当前渲染画布尺寸）
  // layers   数组：JSON 里声明的每个图层的**基准状态**
  //          [{ x, y, w, h, alpha, scale, offset_y }, ...]

  // 必须返回**等长数组**，每项是"相对基准的增量"
  return layers.map((L) => ({ dx: 0, dy: 0, scale: 1, alpha: 1 }));
}
```

### 返回值的字段

| 字段 | 含义 | 默认 |
|---|---|---|
| `dx` / `dy` | 相对基准位置的**位移**（像素，`dy` 正 = 向下） | 0 |
| `dw` / `dh` | 尺寸增量（像素） | 0 |
| `scale` | **乘**在基准缩放上（`1` = 不变） | 1 |
| `alpha` | **乘**在基准透明度上（`1` = 不变） | 1 |
| `rotate` | 额外旋转（度） | 0 |
| `tint` | 颜色覆盖（`"#RRGGBB"`） | 无 |

**为什么是增量不是绝对值**：这样 JSON 与 JS 天然可以混用，而且**脚本出错时退化到基准值**，而不是「变成 0 跑到画面外」。

⚠ **`dw/dh` 是增量且会被夹到 `>= 0`**：`state.w = max(0, state.w + dw)`。
所以 JSON 里把宽度写成 `"0%"`、再想用 `dw` 去长——**结果恒为 0，那层永远不出现，也不报错**。
要“从无到有”长开，用 `scale`（比例缩放，基准给足宽度），而不是 `dw`。

⚠ 这张表是**全部可用字段**。写了表外的键（如 `sx`/`sy`）**静默忽略**，不报错。
想做各向异性形变，用 `scale` + `dw/dh` 组合近似。

## 2.5 可用的宿主函数（白名单）

脚本只能调这些，**没有**任何“读时钟/随机/文件/网络”的入口——那是确定性的前提。

| 函数 | 返回 | 用在哪里 |
|---|---|---|
| `ease(name, t)` | 0~1 | 标准缓动。`name` 取 `linear`/`in`/`out`/`in_out`/`back`/`elastic`/`expo_out`/`expo_in_out`/`smoother` |
| **`spring(tau, zeta, omega)`** | 0→1 | **二阶阶跃响应**（从 0 起、趋于 1，可过冲）。`zeta` 阻尼比：0.4 很跳 / 0.6 舒服 / 0.8 稳重 / 1 不回头；`omega` 频率：14 慢 / 20 中 / 26 快 |
| **`spring_vel(tau, zeta, omega)`** | 每秒进度 | `spring` 的导数。用于**由速度驱动的形变**（落地瞬间压扁、停稳归零）|
| **`settle(zeta, omega, eps)`** | 秒 | 弹簧多久后稳定。用来排节奏：“这一弹占 0.62s，然后切镜” |
| `lerp(a, b, t)` | 数 | 线性插值 |
| `clamp(v, lo, hi)` | 数 | 限幅 |
| `snap(t, fps)` | 数 | 吸附到帧 |
| `noise(seed)` | 0~1 | **确定性**伪随机（同种子同结果）|

### 为何弹簧不是一种 `ease`

`ease(name, t)` 的 `t` 是**已归一化的进度**，它描述“走到终点了吗”；
而弹簧的自变量是**时间**——它没有预设终点时刻，靠 ζ/ω 自己决定何时停。
硬当成 `ease` 会丢掉“到 1 之后继续超调再回来”——**而那正是“有质量”的来源**。

用同一套 ζ/ω 驱动所有元素，就是“所有东西都是同一种 S 曲线”的根源。
不同角色给不同参数：主角色过冲（ζ 0.5），辅助线干脆（ζ 0.85）。

## 3. 六个稳定性保障（写的时候可以依赖）

这是本层为"AI 生成也能稳"专门设计的，不是自然长成的：

### 3.1 语法错在**加载时**就报，不是渲到一半

```
脚本编排层语法错误：脚本错误: SyntaxError: ...
      at layout.js:12:5
```

### 3.2 `layout` 没定义 / 不是函数 → 加载时立刻拒绝

不会出现「能加载但永远不生效」这种最难查的状态。

### 3.3 脚本抛错/死循环 → **降级为纯 JSON**，不崩

单帧失败只影响那一帧（用基准值），导出继续。
`failure_count()` 累计次数，导出结束可汇总报告。

> 实测过的边界：`while(true){}` 会在 400ms 被打断，
> 而不是挂死 342 帧的导出。

### 3.4 `NaN` / `Infinity` → 当"没写这个字段"处理

```js
return [{ dy: NaN }];   // → dy 按 0 处理，其余字段照常生效
```
不会让整帧失败。（这条是实现里专门在 JS 侧做的清洗——`NaN` 不是合法 JSON。）

### 3.5 返回数组长度不符 → 按较短者填，缺的保持基准

```js
return [{ dx: 5 }];     // 只有第一层生效，其余保持 JSON 原样
```
一处疏漏不毁整帧。

### 3.6 确定性：同一脚本 + 同一时间 ⇒ 同一结果

脚本里**读不到时钟、随机数、文件、网络**（这些没注册）。
所以同一帧渲两次逐像素相同——批量导出与回归比对都依赖这条。

## 4. 能做什么 / 不能做什么

| 能 | 不能 |
|---|---|
| 循环、条件、数学 | 新增图层（图层集合来自静态 JSON） |
| 读写传入的 `layers` 基准值 | 加载素材 / 读文件 / 发网络请求 |
| 调用内置数学（`Math.*`） | 读系统时钟、随机数（**故意不给**，为了确定性） |
| 一次算出整帧所有图层 | 改渲染管线 / 创建新的图层类型 |

**为什么"不能新增图层"**：一旦脚本能造图层，渲染就不再是
`(Scene, t) → 像素` 的纯函数，并行导出与逐像素可复现都会崩。
而"只算数值"能覆盖绝大多数真实需求——所有动画本质都是数值随时间变化。

## 5. 一个完整例子

```js
// 12 个图标：错峰升起 + 入场后持续起伏
function layout(t, duration, canvas, layers) {
  const out = layers.slice();
  for (let i = 1; i < out.length; i++) {     // [0] 是桌面块，不动
    const delay = (i - 1) * 0.12;            // 每个比前一个晚 0.12s
    const local = Math.max(0, t - delay);
    const p = Math.min(1, local / 0.7);
    const ease = 1 - Math.pow(1 - p, 3);     // ease-out

    const wave = Math.sin(t * 2.2 + i * 0.9) * 26 * Math.min(1, local / 0.9);

    out[i] = {
      dy: (1 - ease) * 220 + wave,           // 从下方升上来
      scale: 0.82 + 0.18 * ease,
      alpha: 0.15 + 0.85 * ease,
    };
  }
  return out;
}
```

**同样效果用 JSON 要写**：12 个图层各一套 `path_*` + `bounce_*` +
不同的 `enter_at`（错峰）—— 而且「入场后持续起伏」用现有字段
**根本表达不了**。

## 6. 排查

### 6.1 `shapes` 画不出来（最耗时的一类）

「改了 layout 脚本，画面一字不变」有**四种原因，症状完全一样**（都不报错）。
先跑一次带诊断的渲染，把四个选项分开：

```
CAIYUN_SHAPES_DEBUG=1 caiyun --headless --script x.json --render /tmp/diag.mp4
```

输出长这样（1080p）：

```
[shapes] loaded=true count=110
[shapes] bbox=(-152303,-80423)-(428161,293846)  in_view=67/110  alpha~0=0
[shapes] kind 分布: circle=70 rect=39 line=1 text=0
[shapes] #0  kind=1 (-143639,-80423) 571800x374269 rgba=(36,26,8,255)
[shapes] #2  kind=1 (1316,495) 82x85 rgba=(255,0,255,242)
```

| 症状 | 对应哪一行 | 修法 |
|---|---|---|
| 脚本没装载 | `loaded=false` | 看 `st` 日志的「装载失败，已降级为纯 JSON」 |
| layout 里某个分支没进 | `count` 比预期少 | 那一帧的条件写错了，用固定颜色探针确认 |
| 图元在画布外 | `in_view` 远小于 `count`，或打 `⚠ 没有任何图元落在画布内` | **坐标忘了按屏幕像素给** |
| 图元被盖住 | `#0` 是尺寸巨大（如 `571800x374269`）的不透明块 | 把要显示的东西 push 到它**之后** |

### 6.1.5 `t` 是**场景内局部时间**，不是全片时间（最贵的一条）

`layout(t, duration, canvas, layers)` 的第一个参数是**本场景内已过的秒数**，
从 0 开始、到 `duration` 结束。**不是全片时间轴上的位置**。

实测代价：为了给"第 7 秒那一段"加东西，我写了 `if (t > 6.9 && t < 7.1)`，
然后反复调参数、反复渲染、反复奇怪"为什么没反应"。真相是第 7 秒落在
**场景 2**（3.8 秒长），那里的 `t` 只有 **约 1.4** —— 那个条件**永远不成立**。

**判据**：想给某个场景加东西时，先算出它在本场景内的局部时间
（`全片时刻 - 该场景起点`），或者干脆**按 `duration` 分派**
（本片 9 个场景的 duration 各不相同，是最稳的键）。

### 6.1.6 让"静止占比"下降，需要**明暗在跳**，不是位置在移

这是量化结论，不是口味问题。

`ot_bench` 的口径是 **32×18 网格（每格 60px）、逐格均值差 <1.2 算静止**。
于是两类运动**测不到**：

| 做法 | 为什么测不到 |
|---|---|
| 点阵/图形**匀速平移** | 相邻帧的格均值几乎相同（同样多的亮点，只是位置差几像素） |
| **密集连续**的点阵旋转 | 每帧只挪 13px（半径 430 × 0.03 rad），而点密到亮度连续 |
| 纯色大块整体移动 | 格均值完全不变 |

**能测到的**：

- 明暗本身在跳（亮→暗、暗→亮的**切换**），幅度够大
- 图形的**存在感**在变（一根线从 8% 长到 92%，而不是平移）
- 位移**跨过整格**（>60px）且图元稀疏（点之间有背景光）

### 6.1.7 尺寸 × alpha 的定量门槛

`tools/layout_alpha_probe` 实测（底色 luma 13.8、点色 luma 161.0，差 147）：

```
Δ ≈ (点面积 / 3600) × 147 × alpha
```

达标（Δ ≥ 1.2）的安全组合：

| 点直径 | alpha | 实测 Δ |
|---|---|---|
| 8 | 0.70 | 1.42 |
| **13** | **0.25** | **1.35** |
| **20** | **0.10** | **1.34** |
| 34 | 0.10 | 3.87 |

直径 6 + alpha 0.10 只有 **0.12** —— 差一个数量级，这正是"改了像没改"的原因。
**先按这张表定参数，再去调观感**，不要反过来。

### 6.1.8 三条"数值上"的规律（离线实验 + 真实画面双向验证）

用 32×18 网格（每格 60px）离线算过一组对照，再回到真实画面复核。

| 手法 | 参数 | 网格差 |
|---|---|---|
| 90 个 26px 点，移 30px | 对比 180 | 5.19 |
| 同上，移 60px | 对比 180 | 8.10 |
| 全宽扫描带，移 30px | 对比 90 | 5.00 |
| **整屏亮度变化 dL** | — | **= dL（1:1）** |
| **网格线位移 = 间距整数倍** | 间距 60 移 60 | **0.00** |

**① 整屏亮度变化是最省的手法**：`dL` 与网格差**严格 1:1**。
把整屏压暗/提亮 3 级，就是 3.0 的变化 —— 比堆几百个图元便宜得多。

**② 位移是周期整数倍 → 完全重合，差 0.00**。
间距 60 的网格移 60px，图元落到**原来的格子里**，逐帧差精确为零。
这是"明明在动却测不到"最隐蔽的一种。

**③ 幅度大 ≠ 速度快**：`sin(t*0.11)*46` 的位移幅度有 46px，
但**瞬时速度**只有 1.06px/帧 —— 实测逐帧差 0.19。
要跨格，瞬时速度需 ≥15px/帧（60px 格 / 4 帧）。

**④ 低 alpha 混色的绝对亮度变化约等于 `bg × a`**。
深底（luma 13）上 `alpha 0.06` 只产生 `dL ≈ 0.01` —— 完全测不到。
**深底上做淡纹理是性价比最低的做法**：要么把 alpha 提到 0.25 以上，
要么改做"整屏亮度变化"。

### 6.2 两条硬规则（不知道就会白改好几轮）

1. **`shapes` 收的是屏幕像素，不过相机**。`paint_script_shapes` 里每个图元只乘
   `S = 画布宽/1920`（1920 宽时就是 1），**zoom 完全不参与**。所以写 `120` 就是画面
   上 120px；写 `120/Z` 会得到亚像素，看起来像没画。
2. **后 push 的在上面**。`shapes` 按数组顺序叠。把纹路写在页面底块之前，会被那块
   （高倍下 `w=571800`）整片盖掉——而它**不报错、不警告**。

### 6.3 其他

| 现象 | 查什么 |
|---|---|
| 完全没动画 | 场景里 `layout` 字段写了吗？`st` 日志里有没有「装载失败，已降级」 |
| 部分图层不动 | 返回数组长度够吗？该项是不是返回了 `null` |
| 某个值不生效 | 是不是 `NaN`/`Infinity`（会被当没写处理） |
| 导出变慢 | `layout` 每帧每图层都要算；检查超时是否频繁触发（`failure_count()`） |
| 用 node 单跑报 `ease is not defined` | **正常**——`ease` 由引擎注入，不是脚本 bug |

打开日志看装载结果：失败会打 `脚本编排层装载失败，已降级为纯 JSON：<原因>`。

### 6.4 「动得不够」怎么量

`shapes` 的坐标是屏幕像素，而验收量尺是 **32×18 网格（每格 60px）**。
所以：

- **小于 60px 的位移测不到**（格均值几乎不变）。实测 22px 漂移只把逐帧差从
  `0.00` 抬到 `0.12`；要可测，位移要能**跨过一整格**。
- **纯色大块移动也测不到**（整块平移，格均值不变）。参考片那一格荧光像素是
  **字符格**（内部明暗交替），一动就跨过网格边界。纯色块要先拆出内部结构。
