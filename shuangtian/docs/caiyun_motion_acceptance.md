# 裁云 · 动效验收手册（三层判据）

> **这份文件回答**：一条动效片「像不像 PPT」怎么量。
> 对标 [onetake](https://github.com/feitangyuan/onetake) 的 `verify_promo.py`，
> 但我们用**自己的实现**（C++ 工具 + 自研渲染器）。

---

## 一、为什么需要它（这是本项目最贵的一课）

用户说「太粗糙」时，开发者无法定位——没有量尺。
更糟的是：**做了一版"看起来进步"的东西，量出来分数还更高，但用户仍然说差**。

本项目实测走过的三个弯路：

| 弯路 | 表现 | 真实原因 |
|---|---|---|
| 只用「画面沿用率」 | 我们 v1 得 0.938，onetake 官方片 0.763——**我们「更连贯」** | 大片黑场下相对峰值判据失真，分数虚高 |
| 只看重叠率判「有没有动」 | 逐帧 MD5 **16 帧全不同**，判据却报「有效变化 8.5%」 | 亮块门槛（峰值 35%）把细曲线判成「不亮」 |
| 把内容「做小」当高级感 | 内容只占画面 15%，画面 85% 是空的 | onetake 的「小」指**元素小**，不是**内容区小** |

**结论**：量尺本身会错，而且错的方式很隐蔽——数字看起来「正常」，只是方向反了。
所以每次改判据，都必须拿**已知好片**（onetake 官方成片）当基准重新校准。

## 二、三层判据（缺一不可）

### 第一层 · 画面沿用率（carry ratio）

**量什么**：相邻两帧，上一帧的亮块有多大比例在下一帧还亮着。
**判什么**：画面是「长出来」的，还是「换上去」的。
**阈值**：均值 ≥ 0.5（onetake 的红线）。

**两个必须注意的口径**：
- **必须有绝对下限**（我们用 18/255）。只用「相对峰值 35%」时，大片黑场的片子会虚高。
- 报告时必须注明是**均值**还是中位数——同一批数据两者能给相反结论。

### 第二层 · 元素身份延续率（identity carry）

**量什么**：按**元素名字**配对，上一帧的元素有多大比例在下一帧还出现在附近
（位移上限取画面宽度的 25%）。
**判什么**：画面「那块地方还亮着」但「元素换了」——这是幻灯片，第一层抓不到。

**前置条件**：渲染时要导出 `trajectory.tsv`
（`caiyun --render ... --track-elements`），记录每个元素每帧的屏幕矩形。

### 第三层 · 变化强度（mean abs delta）—— **最容易漏的一层**

**量什么**：相邻两帧在 32×18 网格上的**平均绝对亮度差**（0~255）。
**判什么**：这一帧到底动了多少。**不设亮度门槛**，所以对细线、小点也敏感。

**为什么必须有这一层**：第一、二层都可能「因为画面静止而看起来很好」。
一个几乎不动的片子，沿用率接近 1、身份延续率 1.0——两个指标都满分。
第三层是唯一能把「静止」暴露出来的。

## 三、实测基准（**必须同采样间隔**）

> ⚠ **这一节曾经给错结论，代价是两轮返工。**
> 最初拿 10 fps 抽的参考片与 30 fps 抽的自己的片比，得出「差 5.3 倍」。
> 而采样间隔差 3 倍，运动量本来就该差 3 倍。
> **两个不同 fps 的帧目录不可比。** 工具现在会打印采样间隔并给出警告。

### 同口径（都 30 fps，步长 1）

| 片子 | 网格平均绝对差 | 有效变化帧对 |
|---|---|---|
| onetake 官方 one-dot | **1.09** | 35.2% |
| 我们 v4 | 0.51 | 42.8% |
| 我们 v5（按真实结构重做） | 0.26 | 12.7% |

**v5 的低分是「结构对了但内容密度不够」**——它允许大量静止（这是对的方向），
但每个场所的元素量与运动量比参考片少得多。这不是判据问题。

### 判读要点

- **均值会被尖峰支配**：onetake 逐帧均值 1.09，但中位数只有 ~0.4，
  因为 10.0s / 11.4s 两处尖峰高达 **40~48**（长句横掠整屏）。
  只看均值会误判「它全程都很动」。**必须同时看中位数与逐秒分布。**
- **最大值的量级差是最硬的信息**：参考片峰值 48.8，我们只有 4.8。
  这说明「强运动段」的强度差一个数量级。
- **有效变化率与强度是两件事**：可以「大多数帧在微微动」（高变化率、低强度），
  也可以「大多数帧静止 + 几次剧烈运动」（低变化率、高强度）。
  **两者没有优劣，取决于片子风格**——但必须与参照片同型。

## 四、尺度事实：微动的**下限**在哪里

这一条是实测踩出来的、反直觉的结论。

**先看数据**（同一把尺，32×18 网格，30 fps）：

| | 变化强度中位数 |
|---|---|
| 参考片（拿它当基准） | **0.196** |
| 我们 v5 | **0.006** |
| 我们 v5 + 1~2 px 呼吸微动 | 0.006（**没变**） |

两个事实：

1. **参考片每一帧都有 0.2 左右的持续微动**（中位数 0.196）；
   它的「静止」不是冻结，是**缓慢的几十像素级运动**。
2. **1~2 px 的位移完全测不出来**：32×18 网格在 1080p 下每格 60×60 px，
   1 px 位移被格内平均抹掉，逐帧差值仍是 0.00。

**结论**：想制造「活着的观感」，微动幅度必须是**几十像素**级（或整个元素做缓位移），
而不是 1 px 抗锯齿式的抠。

推论：**判据的分辨率决定了能验收什么**。
要验收真正的细微观感（字形呼吸、微颤），得用更细的网格（如 96×54）
或逐元素追踪，而不是靠 32×18 平均差。

## 五、工具：`motion_qa`（通用动效验收）

```bash
# 单条片自检
motion_qa --dir out/film/frames --fps 30

# 与参考片同口径对照（**推荐**：绝对阈值不可迁移，相对关系才可靠）
motion_qa --dir out/mine/frames --ref ref_frames --fps 30

# 带元素追踪
motion_qa --dir out/film/frames --traj out/film/trajectory.tsv --fps 30\
          --ref ref_frames --ref-traj ref_trajectory.tsv

# 导出逐帧数据（自己画图 / 定位哪一秒闷）
motion_qa --dir out/film/frames --fps 30 --csv out/motion.csv
```

它是**一般工具**，不绑定裁云：任何渲出 PNG 帧序列的管线都能用。

输出会给出：均值 / **中位数** / **p95** / **峰值** 四个数，以及「均值÷中位数」的节奏诊断。

**为什么要看四个数而不是一个**：

| 形状 | 均值 | 中位数 | 峰值 | 含义 |
|---|---|---|---|---|
| A | 高 | 高 | 中 | 持续运动（信息流型） |
| B | 高 | **低** | **很高** | 大部分静止 + 少数剧烈（一镜到底型） |
| C | 低 | 低 | 低 | 真的什么都不动（坏） |

**A 与 B 不分优劣，都是合法风格；C 才是问题。**
只看均值会把 A 和 B 当成同一种东西。

## 六、让静止段「安静而不冻结」：背景颗粒

这是本轮最有价值的单点发现。

**现象**：对标片的「静止段」看起来安静但活着，我们的看起来像卡住了。
数字上就是中位数 0.196 vs 0.006（差 33 倍）。

**根因**：对标片的背景不是纯色，而是**持续闪烁的细颗粒**（稀疏、接近纯白）。
0.196 里有一部分就是这个撑起来的——它占画面小but每帧都在变。

**用法**（场景级字段，不是图层）：

```jsonc
{
  "grain": 3000,        // 颗粒数（0 = 关）
  "grain_alpha": 0.7,    // 亮度（0.05~0.9）
  "accent": "#0a0a14"    // 重要：默认 accent 是亮蓝，会整幅铺光把背景搞成灰蓝
}
```

**实测曲线**（1080p、32×18 验收网格、30 fps；同一部片只改 grain）：

| grain | grain_alpha | 剂量 | 变化强度中位数 | 成片体积 |
|---|---|---|---|---|
| 5000 | 0.34 | 1700 | 0.087 | 3.5 MB |
| 12000 | 0.30 | 3600 | 0.116 | **2.0 MB** |
| 12000 | 0.38 | 4560 | **0.147** | **2.3 MB** |
| 12000 | 0.50 | 6000 | **0.193** | 25 MB（!） |

参考片（onetake）静段中位数 **0.196**。

**四条实测结论**：

1. **“3000 颗饱和”只在低分辨率下成立**。1080p 下 1px 颗粒在 60×60px 的验收格子里
   只覆盖约 0.6%，要到**上万颗**才量得出来。旧上限 2000 在本尺寸几乎测不出。
2. **剂量 = grain × grain_alpha 近似线性**，但实测 5500 剂量给 0.183，
   线性外推是 0.307 ⇒ **已开始饱和**（颗粒重叠）。
3. **体积对 alpha 极敏感且非线性**：0.38 → 2.3 MB，0.50 → 25 MB（**11 倍**）。
   颗粒是高频高对比小点，编码器在它上面极耗码率。
   **实用平衡点在 alpha 0.38~0.42**（中位数 0.15~0.17，体积 <4 MB）。
4. **“每帧整片重分布”比“缓慢漂移”更有效**：试过加整体漂移（更像真实浮尘），
   中位数反而从 0.49 掉到 0.44——漂移让相邻帧颗粒位置接近，差值更小。

> ⚠ **口径警告**：上表的中位数是 32×18 网格口径。换更细的网格（如 96×54），
> 颗粒会被量得更充分，绝对值会变高——**判读时必须连着网格尺寸一起报**。

**两个坑**：
- **不透明全屏 `rect` 图层会盖掉颗粒**（它是背景层，颗粒在它下面）。要么删掉那层，
  用 `background` 字段提供底色；要么把颗粒层挪到它上面。
- **`accent` 默认是亮蓝 `{110,168,255}`**，`paint_backdrop` 会用它做整幅 `wash_vertical`，
  在纯黑底上形成明显灰蓝雾。要干净深黑就把 `accent` 改成近黑。

## 七、横向参考：我们 v5 距参考片的清单

| 指标 | 我们 v5 | 参考片 | 倍数 |
|---|---|---|---|
| 变化强度中位数 | 0.006 | 0.196 | **0.03×** |
| 强度 p95 | 1.673 | 4.531 | 0.37× |
| 强度峰值 | 5.19 | 48.83 | 0.11× |
| 有效变化率 | 12.7% | 35.2% | — |
| 画面沿用率 | 0.961 | 0.874 | — |

**每一项都在同一个方向**：我们的片子比参考片“冷”一个数量级。
三个最有用的差距：

- **中位数 0.03×** → 平时也不动（最严重）；
- **峰值 0.11×** → 强运动段不够强（长句横掠时长/幅度都要再大）；
- **沿用率反而更高** → 又一个“动得太少”的信号。

## 四、怎么用（命令）

```bash
# 1) 渲染并导出元素轨迹
caiyun --headless --script film.json --render out/film.mp4 --track-elements

# 2) 三层判据一次跑完（推荐与参考片同口径对照）
motion_qa --dir out/film/frames --traj out/film/trajectory.tsv --fps 30 \\
          --ref ref_frames
```

输出形如（实际输出）：
```
[片子] 450 帧，网格 32×18，步长 1（采样间隔 33.3 ms）
  画面沿用率   均值 0.961
  变化强度     均值 0.260 · 中位数 0.006 · p95 1.673 · 峰值 5.19
  有效变化     57 / 449 = 12.7%（门槛 0.35）
  判读：均值被尖峰支配，**必须与中位数/峰值一起看**；
        均值高 + 中位数低 = 「大部分静止 + 少数剧烈运动」。
[参考] ……

=== 同口径对照 ===
  变化强度中位数 0.006 vs 0.196  → 0.03×
  诊断：
    · 片子：均值/中位数 = 43.2 → 大多数帧**几乎完全冻住**
    · 参考：均值/中位数 = 5.6 → 静止为主 + 少数强运动段
```

**判读顺序**：
1. **变化强度中位数**（先看它——它代表「绝大多数帧平时的状态」）；
2. **均值÷中位数**（判断节奏类型：>12 完全冻住 / >4 静止为主 / ≤4 均匀）；
3. **峰值**（强运动段的强度够不够）；
4. 最后看沿用率（它只在「有变化」的前提下才有意义）。

## 五、逐秒定位（改片子时最有用）

平均差只给总分，改片子需要知道**哪一秒闷**。做法是按秒采样算差值并打条形图：

```
  秒   Δ/255  条形
  7.5    0.27  ###          ← 曲线段几乎不动
 13.5    0.10  #            ← 字标定住后静止
```

实测靠这个定位到三处「静止段」（1.0–1.5、7.0–9.5、13.5–15），
针对性加强后总分从 0.21 提到 0.52。

## 八、让画面持续活着：环境层（本轮实测的正面手法）

> ⚠ **先读这一条：静止占比是参考量，不是硬指标。**
>
> 它回答的是"这一段是不是卡住了"，**不回答"这里该不该动"**。
> 实测代价：为了把全片静止占比从 82% 压到 28%，给每一幕都套了同一套呼吸 + 快扫——
> 包括收尾字标镜头，于是字标每 2.9s 被一道光扫过，读起来是"莫名地动"。
> **指标好看了，设计反而变差**——这是指标牵引设计的典型形态。
>
> 用法：用它**定位**哪一幕确实卡住了（单幕 >70% 值得看一眼），
> 再问"这一幕本来该不该动"。主体自己在持续运动的镜头（点阵波前、沿环流动、卡片错峰）
> **不需要额外环境层**；需要安静收尾的地方，数字不合格也是对的。

下面各节说的是"确实需要让一个大块静止的镜头活着"时**怎么做**，不是"每幕都这么做"。

### 8.1 八种手法的实测排序（同口径：32×18 网格、帧差 <1.2 记静止）

一条 2.2s 的稳定版面（12 张卡片）作底，每次只加一种动态层：

| 手法 | 参数 | 静止占比 | 中位数 |
|---|---|---|---|
| 裸版面（无动态层） | — | **100.0%** | 0.02 |
| 竖向数据流 | 70 条，420~940 px/s | **100.0%** | 0.35 |
| 全屏光带横扫 | 1900 px/s | **100.0%** | 0.93 |
| 大块快穿 | 14 块 220×40，1400~2600 px/s | **100.0%** | 0.93 |
| 扩散环 | 3 环，1.35s 一圈 | **100.0%** | 0.56 |
| 光斑漂移 | 2 个 520~640px 斑块 | **100.0%** | 0.05 |
| 场景级 `grain` | 1100 / alpha 0.12 与 2400 / 0.22 | **100.0%** | 0.01 |
| **整屏亮度呼吸** | alpha 摆幅 0.045，周期 0.66s | **29.8%** | **1.98** |
| **呼吸 + 扩散环** | 同上 + 环 0.9 | 63.1% | 1.12 |
| **呼吸 + 环 + 快扫** | 同上 + 1750 px/s | **36.9%** | 1.38 |
| **呼吸 + 环 + 大块** | 同上 + 12 块 | **27.7%** | 1.46 |

**两条可直接用的结论**：

1. **单层几乎全部 100% 静止**——包括看起来"肯定在动"的数据流与快扫。
   原因是格均值：形状在格间移动时，只要每格里的"平均亮度"不变，就测不到。
2. **呼吸是唯一能单独过线的手法**，因为它直接改整屏亮度（`dL` 与格差**1:1**）；
   再叠两层只是把静止占比从 30% 压到 27%，**边际收益递减**——
   所以不要"堆很多手法"，要选正交的：一团亮度波 + 一个存在感变化 + 一个跳格位移。

### 8.2 呼吸的幅度与周期要**算**，不要拍脑袋

正弦呼吸（`alpha = lo + (hi-lo)·(0.5+0.5·sin(2πt/T-π/2))`）的逐帧格差近似：

```
Δ ≈ A · 4 / (T · 30)        A = luma 摆幅（8bit 级），T = 周期（秒），30 = fps
```

实测校验：A=11.5、T=0.66 → 公式 2.32，实测中位数 **1.98**（公式偏乐观 ~15%，可用于定参）。

于是"安静但不冻结"的可行区很窄：

| A（级） | T（s） | 算出的 Δ | 判 |
|---|---|---|---|
| 5.1 | 0.90 | 0.76 | 太静（实测 0.88） |
| 6.1 | 0.78 | 1.04 | 临界 |
| **6.1** | **0.62** | **1.31** | 过线 |
| 9.2 | 0.62 | 1.98 | 稳 |

**关键**：想让收尾段"静得住"，只能**缩周期**，不能缩幅度（缩幅度直接掉到 0.5）。
代价是呼吸变快——但 0.62s 在成片上读作"呼吸"，不是频闪；0.26s 才是频闪（不要）。

### 8.3 呼吸必须画在**内容之后**（最贵的一条）

分两层写：

```js
function envBackdrop(...) { /* 扩散环、纹路、细流——背景层 */ }
function envOverlay(...)  { /* 呼吸 + 快扫——必须在所有内容之后 */ }

// 场景里的顺序就是层序：
function layout(t, duration, canvas, layers) {
  const sh = [];
  envBackdrop(sh, ...);   // ① 背景
  /* …主体内容… */        // ② 内容（卡片、终端窗口、点阵）
  envStream(sh, ...);     // ③ 细节
  envOverlay(sh, ...);    // ④ 呼吸 + 快扫（最上）
  return { states: ..., shapes: sh };
}
```

实测代价：第一版把呼吸写在背景层，幕 4 的终端窗口把整屏盖住 → 那一幕**95% 静止**，
推镜与环境层全白做。

### 8.4 三种强度档（本片最后用的参数）

| 档 | 用在哪 | hi（alpha 峰值） | 周期 | 环 | 快扫 |
|---|---|---|---|---|---|
| 0 安静 | 收尾/字标落定段 | 0.055 | 0.62s | 0.7× | 1450 px/s |
| 1 常规 | 叙事幕 | 0.052 | 0.64s | 1.0× | 1750 px/s |
| 2 峰值 | 尺度揭示/扩张 | 0.058 | 0.64s | 1.15× | 2050 px/s |

> "安静"档的 hi 反而**略高于**常规——因为安静段没有主体运动帮忙，只能靠呼吸自己撑。

### 8.5 逐幕验收的读法

全片均值会把问题掩盖掉（本片第一版全片 82%，而逐幕 73~89% 全都不过）。
**逐幕必看**，且判据要比全片更严（单幕 >70% 就是那一幕的问题）：

```bash
py examples/caiyun/gbfilm/measure.py film.mp4 --scenes 4.6,5.2,5.8,5.4,6.0,5.4,6.0
```

该脚本与验收器同口径（结果可与渲染日志的「画面质量」行对账），
并标注哪一幕不过——**先改那一幕，不要改全片**。

## 六、反模式（每条都实测踩过）

| 反模式 | 后果 |
|---|---|
| 只用一个指标宣布"更连贯" | 静止的片子会拿满分 |
| 拿自己的上一版当基准 | 只说明"比上次好"，不说明"够不够" |
| **改判据后不重测已知好片** | 判据可能整体偏移，而数字看起来正常 |
| 用「元素小」当「内容少」的借口 | onetake 是元素小、内容占满；我们做成了元素小、内容也少 |
| 把「到位」当作一段的结束 | 到位后还要**持续活着**，否则那段就是静止 |
| 亮柱/大色块当"扫光" | 会直接挡住文字，很丑。扫光应该是极淡的大面积柔光 |
| **把运镜（`cam_zoom`）当"让画面活着"** | `shapes` **不过相机**，对脚本图元完全无效；推镜要自己在脚本里算坐标 |
| **堆很多层动态手法** | 单层几乎都 100% 静止，但三层之后边际收益递减（30%→27%）。要**正交**不要多 |
| **用 `grain` 当"在动"的证据** | 实测 1100~2400 颗都是 100% 静止；它是质感层，不是运动证据 |
| **为了护住文字可读性盖一层半透明深色底** | 边缘硬、颜色跳，成片上一个黑方地。降周围元素的强度即可，不要造新形状 |
| **按 `duration` 在一个 layout 文件里分派多幕** | `Math.abs(D - index) < 0.6` 时 4.6s 的幕被判成幕 4，且 5.4/6.0 被两幕共用——画面全错而渲染"成功"。**每幕一个 layout 文件** |
