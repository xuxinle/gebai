# 裁云 · 动效验收手册（三层判据）

> **这份文件回答**：一条动效片「像不像 PPT」怎么量。
> 对标 [onetake](https://github.com/feitangyuan/onetake) 的 `verify_promo.py`，
> 但我们用**自己的实现**（C++ 工具 + 自研渲染器）。

---

## 一、为什么需要它（这是本项目最贵的一课）

用户说「太粗糙」时，开发者无法定位——没有量尺。
更糟的是：**做了一版"看起来进步"的东西，量出来分数还更高，但用户仍然说差**。

本项目实测走过的三个弯路：

| 弯路 | 表现 | 真实原因 |
|---|---|---|
| 只用「画面沿用率」 | 我们 v1 得 0.938，onetake 官方片 0.763——**我们「更连贯」** | 大片黑场下相对峰值判据失真，分数虚高 |
| 只看重叠率判「有没有动」 | 逐帧 MD5 **16 帧全不同**，判据却报「有效变化 8.5%」 | 亮块门槛（峰值 35%）把细曲线判成「不亮」 |
| 把内容「做小」当高级感 | 内容只占画面 15%，画面 85% 是空的 | onetake 的「小」指**元素小**，不是**内容区小** |

**结论**：量尺本身会错，而且错的方式很隐蔽——数字看起来「正常」，只是方向反了。
所以每次改判据，都必须拿**已知好片**（onetake 官方成片）当基准重新校准。

## 二、三层判据（缺一不可）

### 第一层 · 画面沿用率（carry ratio）

**量什么**：相邻两帧，上一帧的亮块有多大比例在下一帧还亮着。
**判什么**：画面是「长出来」的，还是「换上去」的。
**阈值**：均值 ≥ 0.5（onetake 的红线）。

**两个必须注意的口径**：
- **必须有绝对下限**（我们用 18/255）。只用「相对峰值 35%」时，大片黑场的片子会虚高。
- 报告时必须注明是**均值**还是中位数——同一批数据两者能给相反结论。

### 第二层 · 元素身份延续率（identity carry）

**量什么**：按**元素名字**配对，上一帧的元素有多大比例在下一帧还出现在附近
（位移上限取画面宽度的 25%）。
**判什么**：画面「那块地方还亮着」但「元素换了」——这是幻灯片，第一层抓不到。

**前置条件**：渲染时要导出 `trajectory.tsv`
（`caiyun --render ... --track-elements`），记录每个元素每帧的屏幕矩形。

### 第三层 · 变化强度（mean abs delta）—— **最容易漏的一层**

**量什么**：相邻两帧在 32×18 网格上的**平均绝对亮度差**（0~255）。
**判什么**：这一帧到底动了多少。**不设亮度门槛**，所以对细线、小点也敏感。

**为什么必须有这一层**：第一、二层都可能「因为画面静止而看起来很好」。
一个几乎不动的片子，沿用率接近 1、身份延续率 1.0——两个指标都满分。
第三层是唯一能把「静止」暴露出来的。

## 三、实测基准（**必须同采样间隔**）

> ⚠ **这一节曾经给错结论，代价是两轮返工。**
> 最初拿 10 fps 抽的参考片与 30 fps 抽的自己的片比，得出「差 5.3 倍」。
> 而采样间隔差 3 倍，运动量本来就该差 3 倍。
> **两个不同 fps 的帧目录不可比。** 工具现在会打印采样间隔并给出警告。

### 同口径（都 30 fps，步长 1）

| 片子 | 网格平均绝对差 | 有效变化帧对 |
|---|---|---|
| onetake 官方 one-dot | **1.09** | 35.2% |
| 我们 v4 | 0.51 | 42.8% |
| 我们 v5（按真实结构重做） | 0.26 | 12.7% |

**v5 的低分是「结构对了但内容密度不够」**——它允许大量静止（这是对的方向），
但每个场所的元素量与运动量比参考片少得多。这不是判据问题。

### 判读要点

- **均值会被尖峰支配**：onetake 逐帧均值 1.09，但中位数只有 ~0.4，
  因为 10.0s / 11.4s 两处尖峰高达 **40~48**（长句横掠整屏）。
  只看均值会误判「它全程都很动」。**必须同时看中位数与逐秒分布。**
- **最大值的量级差是最硬的信息**：参考片峰值 48.8，我们只有 4.8。
  这说明「强运动段」的强度差一个数量级。
- **有效变化率与强度是两件事**：可以「大多数帧在微微动」（高变化率、低强度），
  也可以「大多数帧静止 + 几次剧烈运动」（低变化率、高强度）。
  **两者没有优劣，取决于片子风格**——但必须与参照片同型。

## 四、尺度事实：微动的**下限**在哪里

这一条是实测踩出来的、反直觉的结论。

**先看数据**（同一把尺，32×18 网格，30 fps）：

| | 变化强度中位数 |
|---|---|
| 参考片（拿它当基准） | **0.196** |
| 我们 v5 | **0.006** |
| 我们 v5 + 1~2 px 呼吸微动 | 0.006（**没变**） |

两个事实：

1. **参考片每一帧都有 0.2 左右的持续微动**（中位数 0.196）；
   它的「静止」不是冻结，是**缓慢的几十像素级运动**。
2. **1~2 px 的位移完全测不出来**：32×18 网格在 1080p 下每格 60×60 px，
   1 px 位移被格内平均抹掉，逐帧差值仍是 0.00。

**结论**：想制造「活着的观感」，微动幅度必须是**几十像素**级（或整个元素做缓位移），
而不是 1 px 抗锯齿式的抠。

推论：**判据的分辨率决定了能验收什么**。
要验收真正的细微观感（字形呼吸、微颤），得用更细的网格（如 96×54）
或逐元素追踪，而不是靠 32×18 平均差。

## 五、工具：`motion_qa`（通用动效验收）

```bash
# 单条片自检
motion_qa --dir out/film/frames --fps 30

# 与参考片同口径对照（**推荐**：绝对阈值不可迁移，相对关系才可靠）
motion_qa --dir out/mine/frames --ref ref_frames --fps 30

# 带元素追踪
motion_qa --dir out/film/frames --traj out/film/trajectory.tsv --fps 30\
          --ref ref_frames --ref-traj ref_trajectory.tsv

# 导出逐帧数据（自己画图 / 定位哪一秒闷）
motion_qa --dir out/film/frames --fps 30 --csv out/motion.csv
```

它是**一般工具**，不绑定裁云：任何渲出 PNG 帧序列的管线都能用。

输出会给出：均值 / **中位数** / **p95** / **峰值** 四个数，以及「均值÷中位数」的节奏诊断。

**为什么要看四个数而不是一个**：

| 形状 | 均值 | 中位数 | 峰值 | 含义 |
|---|---|---|---|---|
| A | 高 | 高 | 中 | 持续运动（信息流型） |
| B | 高 | **低** | **很高** | 大部分静止 + 少数剧烈（一镜到底型） |
| C | 低 | 低 | 低 | 真的什么都不动（坏） |

**A 与 B 不分优劣，都是合法风格；C 才是问题。**
只看均值会把 A 和 B 当成同一种东西。

## 六、让静止段「安静而不冻结」：背景颗粒

这是本轮最有价值的单点发现。

**现象**：对标片的「静止段」看起来安静但活着，我们的看起来像卡住了。
数字上就是中位数 0.196 vs 0.006（差 33 倍）。

**根因**：对标片的背景不是纯色，而是**持续闪烁的细颗粒**（稀疏、接近纯白）。
0.196 里有一部分就是这个撑起来的——它占画面小but每帧都在变。

**用法**（场景级字段，不是图层）：

```jsonc
{
  "grain": 3000,        // 颗粒数（0 = 关）
  "grain_alpha": 0.7,    // 亮度（0.05~0.9）
  "accent": "#0a0a14"    // 重要：默认 accent 是亮蓝，会整幅铺光把背景搞成灰蓝
}
```

**实测曲线**（同一部片，只改 grain）：

| grain | 中位数 / 参考 |
|---|---|
| 420 | 0.07× |
| 820 | 0.17× |
| 1400 | 0.37× |
| 3000 | 0.49× |
| 6000 | 0.49×（饱和） |

**两条实测结论**：
- **饱和点在 3000 左右**，再加不涨（画面也变成噪点视频了）。
- **“每帧整片重分布”比“缓慢漂移”更有效**：试过加整体漂移（更像真实浮尘），
  中位数反而从 0.49 掉到 0.44——漂移让相邻帧颗粒位置接近，差值更小。

**两个坑**：
- **不透明全屏 `rect` 图层会盖掉颗粒**（它是背景层，颗粒在它下面）。要么删掉那层，
  用 `background` 字段提供底色；要么把颗粒层挪到它上面。
- **`accent` 默认是亮蓝 `{110,168,255}`**，`paint_backdrop` 会用它做整幅 `wash_vertical`，
  在纯黑底上形成明显灰蓝雾。要干净深黑就把 `accent` 改成近黑。

## 七、横向参考：我们 v5 距参考片的清单

| 指标 | 我们 v5 | 参考片 | 倍数 |
|---|---|---|---|
| 变化强度中位数 | 0.006 | 0.196 | **0.03×** |
| 强度 p95 | 1.673 | 4.531 | 0.37× |
| 强度峰值 | 5.19 | 48.83 | 0.11× |
| 有效变化率 | 12.7% | 35.2% | — |
| 画面沿用率 | 0.961 | 0.874 | — |

**每一项都在同一个方向**：我们的片子比参考片“冷”一个数量级。
三个最有用的差距：

- **中位数 0.03×** → 平时也不动（最严重）；
- **峰值 0.11×** → 强运动段不够强（长句横掠时长/幅度都要再大）；
- **沿用率反而更高** → 又一个“动得太少”的信号。

## 四、怎么用（命令）

```bash
# 1) 渲染并导出元素轨迹
caiyun --headless --script film.json --render out/film.mp4 --track-elements

# 2) 三层判据一次跑完（推荐与参考片同口径对照）
motion_qa --dir out/film/frames --traj out/film/trajectory.tsv --fps 30 \\
          --ref ref_frames
```

输出形如（实际输出）：
```
[片子] 450 帧，网格 32×18，步长 1（采样间隔 33.3 ms）
  画面沿用率   均值 0.961
  变化强度     均值 0.260 · 中位数 0.006 · p95 1.673 · 峰值 5.19
  有效变化     57 / 449 = 12.7%（门槛 0.35）
  判读：均值被尖峰支配，**必须与中位数/峰值一起看**；
        均值高 + 中位数低 = 「大部分静止 + 少数剧烈运动」。
[参考] ……

=== 同口径对照 ===
  变化强度中位数 0.006 vs 0.196  → 0.03×
  诊断：
    · 片子：均值/中位数 = 43.2 → 大多数帧**几乎完全冻住**
    · 参考：均值/中位数 = 5.6 → 静止为主 + 少数强运动段
```

**判读顺序**：
1. **变化强度中位数**（先看它——它代表「绝大多数帧平时的状态」）；
2. **均值÷中位数**（判断节奏类型：>12 完全冻住 / >4 静止为主 / ≤4 均匀）；
3. **峰值**（强运动段的强度够不够）；
4. 最后看沿用率（它只在「有变化」的前提下才有意义）。

## 五、逐秒定位（改片子时最有用）

平均差只给总分，改片子需要知道**哪一秒闷**。做法是按秒采样算差值并打条形图：

```
  秒   Δ/255  条形
  7.5    0.27  ###          ← 曲线段几乎不动
 13.5    0.10  #            ← 字标定住后静止
```

实测靠这个定位到三处「静止段」（1.0–1.5、7.0–9.5、13.5–15），
针对性加强后总分从 0.21 提到 0.52。

## 六、反模式（每条都实测踩过）

| 反模式 | 后果 |
|---|---|
| 只用一个指标宣布"更连贯" | 静止的片子会拿满分 |
| 拿自己的上一版当基准 | 只说明"比上次好"，不说明"够不够" |
| **改判据后不重测已知好片** | 判据可能整体偏移，而数字看起来正常 |
| 用「元素小」当「内容少」的借口 | onetake 是元素小、内容占满；我们做成了元素小、内容也少 |
| 把「到位」当作一段的结束 | 到位后还要**持续活着**，否则那段就是静止 |
| 亮柱/大色块当"扫光" | 会直接挡住文字，很丑。扫光应该是极淡的大面积柔光 |
