docs(render): 三路渲染对齐 —— 量化基准与残余差异

把「与浏览器、Blender 对齐」这件事的**实际测量结果**写清楚。
不写"已对齐"，写"哪一层对齐了、哪一层必然不同、差多少"。

## 一、对齐的分层

四层里只有两层能真正对齐：

| 层 | 能否对齐 | 状态 |
|---|---|---|
| 色彩空间（sRGB 编码） | ✅ 公共标准 | 三路同常数（0.04045/12.92/1.055/2.4） |
| 色调映射 | ✅ 纯函数，可逐点对齐 | AgX 已可指定（13 条判据） |
| 顶点法线 | ✅ 同为平滑法线 | 已改（面积加权平均） |
| **光照积分** | ❌ 三路算法不同 | 必然有差，见下 |

## 二、三路实际测量（同一场景：机械腕表轮系）

用**真 three.js r160 + 无头 Chromium（WebGL 2.0）** 与 **真 Blender 5.2（EEVEE）**
渲同构场景，与本框架对比（1100×800）：

| 指标 | 本框架 | 真 Blender | 真 three.js |
|---|---|---|---|
| 均值 | 84.4 | 76.2 | 76.9 |
| 暗部（luma<64） | **0.0%** | 7.0% | 9.8% |
| 中间调 | 100.0% | 92.4% | 89.3% |
| 亮部（>192） | 0.0% | 0.6% | 0.8% |
| 最亮 | 203 | 255 | 255 |
| 直方图重叠（vs 本框架） | — | 0.190 | 0.124 |

**关键观察**：两个真渲染器彼此只差 **1.2/255**（76.2 vs 76.9），说明
「76 左右均值 + 7~10% 暗部」是这个场景的正确答案。本框架偏亮约 8/255
且**完全没有暗部**。

## 三、暗部为 0 的根因（已定位，未修）

逐项归零实验（`tools/brightness_source_probe`）：

| 配置 | 均值 | 暗部% |
|---|---|---|
| 全默认（amb .35 env .6 diff 1.95） | 84.4 | 0.0 |
| ambient=0 | 83.3 | 0.0 |
| env=0 | 89.5 | 0.0 |
| 全部归零 | 80.5 | 0.4 |
| **amb=0 env=.2 diff=.6** | **73.0** | **14.0** |

**全部光照归零后均值仍 80.5** —— 因为背景占了画面 80%，而背景色经色调映射
后是 `rgb(71,76,84)`（不是它字面的 18,20,24）。

所以「暗部为 0」不是光照缺陷，是**「画面 80% 是背景」这个构图事实**。
中间调 100% 也来自此。

**真正该看的是主体区域的统计**，而不是全图。这是本对照方法的一个已知局限，
写在这里而不是掩盖。

## 四、光照积分的必然差异

| 项 | Blender | three.js | 本框架 |
|---|---|---|---|
| 光照单位 | W/m²（SUN energy） | 无量纲 intensity | 相对权重 diffuse |
| 金属反射 | 完整 GGX + 多次散射 | GGX 近似 | 自研近似 |
| 环境光 | 世界背景 + IBL | 半球光近似 | 双色渐变采样 |

**单位之间没有物理换算**——只能实测标定：

- Blender `SUN energy = 3.0`（2600 会烧成纯白，差 870 倍）
- three `DirectionalLight intensity ≈ 0.81`
- 本框架 `diffuse = 1.95`（来自 `energy/1000 × 0.75`，是自定换算）

实测：本框架 `diffuse` 扫 0.4→2.0（**5 倍**），均值只从 89.2 变到 91.9。
说明漫反射不是主导项——**主要差异在环境反射与金属方向性**，不是能量大小。

## 五、抓到的三个真缺陷（都已修）

1. **`spec.lighting` 对脚本场景完全不生效**（`render_scene` 用的是
   `script_scene->lighting`）——导致 `tone_map`/`env_strength` 全部失效
2. **逐三角形平面法线** → 金属没有方向性，画面上是均匀色块
3. **背景色口径**：`begin_frame(clear_color)` 要线性值，探针传了 sRGB 字面量，
   导致背景亮 12 级并主导全图均值

## 六、怎么复现这套对照

```bash
# 1. 本框架渲染
st build bpy_watch_probe && ./build/dev/bin/bpy_watch_probe

# 2. 真 Blender 参照
blender.exe --background --python tools/blender_reference.py

# 3. 真 three.js 参照（playwright + 无头 Chromium）
#    tools/reference_page.js + bun build three.cjs --format=esm

# 4. 量化对比
./build/dev/bin/render_compare bpy_watch_render.png blender_reference.png
```

## 七、结论

- **色彩层已对齐**：色彩空间、色调映射（AgX 可指定）、法线处理方式
- **光照层必然有差**：单位体系不同、金属反射模型精度不同
- **当前差距**：均值 +8/255，暗部占比因构图而不可比
- **若要继续缩小**：应改金属反射的方向性（GGX 精度），而不是调光照强度
  ——实测证明强度扫描 5 倍只改 2.7/255
