# 对标 onetake：能力差距全链路盘点

> 方法：克隆 `feitangyuan/onetake`，读其方法论与 11 条成片，逐项对照我们的裁云栈。
> 结论先行：**我们的差距不在"能不能画出来"，而在四个层面**——
> 运动质量、排版驱动、连贯性验证、以及"细节精度"。

---

## 一、它的技术栈（实测）

| 项 | 实现 |
|---|---|
| 组合 | 单 HTML 文件，`window.__seek(t)` 纯函数 |
| 动作库 | `lib/motion.js`，39 个实测动作（弹簧/入场/衔接/碰撞/镜头/流体） |
| 渲染 | Playwright 逐帧截图，180° 快门**时间超采样** + 线性光平均 |
| 分辨率 | 草稿 1080p30 → 成片 4K60 |
| 验收 | `verify_promo.py`：节奏腿 + 连贯性 carry score + 曲线 + 构图 |
| 声音 | 按 `__events()` 事件摆放，同一混响，−16 LUFS |
| 确定性 | `__seek(t)` 两次同帧；无 `Math.random` |

**它的核心武器不是渲染，是「验收」**：`carry score < 0.5` 直接判不合格。
这让「像 PPT」从主观判断变成可量化的红线。

## 三、四个层面的差距（按影响排序）

### 差距 1 · 运动质量：我们有曲线，没有「实测过的动作」

**它**：39 个动作，每个都是「实测速度曲线」，明确不用随手写的缓动。
**我们**：只有 6 条缓动（linear/in/out/in_out/back/elastic）+ 弹跳。

**缺的关键动作**（从它的片子里能直接看出）：
- **弹簧（spring）**：ζ 阻尼比 / ω 角频率 —— 它片子里明写了 `spring(t, ζ 0.5, ω 26)`
- **吸附（snap）**：expoOut，t80≈0.23 —— 硬切点用
- **错峰（stagger）**：多元素的级联延迟
- **跟随（follow）**：二级元素滞后于主角（overlapping action）

**影响**：我们的动效「软」——所有东西都是同一种 S 曲线。

### 差距 2 · 排版驱动：我们的文字是「一个 text 图层」

**它**：kinetic type —— 每个字母是独立元素，可逐字入场、逐字位移、光标跟随。
**我们**：`text` 图层整体绘制，**无法逐字控制**。

**影响**：做不出「打字机 + 光标跟随 + 逐字弹跳」，而这是这类片子的主语言。
这是**最大的单项差距**。

### 差距 3 · 连贯性验证：我们没有任何 oracle

**它**：每帧记录画面内容 → 找接缝 → 判断有没有东西跨过去 → 打分。
**我们**：靠肉眼。

**影响**：这正是用户最初说「太粗糙」的根因——**没有量尺就无法自我验收**。

### 差距 4 · 镜头语言

**它**：keyed camera + operator 手感（领先半拍、手持浮动、落地震动）、`inFrame` 声明。
**我们**：场景级 `cam_zoom_from/to` 线性推拉，无 lead、无 shake、无追踪。

## 四、补全计划（按"对观感影响 / 实现成本"排序）

| 优先 | 能力 | 为什么 | 预估 |
|---|---|---|---|
| **P0** | **逐字排版（kinetic type）** | 这类片子的主语言；不做就永远做不像 | 大 |
| **P0** | **连贯性 oracle** | 没有它就无法自我验收（"粗糙"无法定位） | 中 |
| P1 | 弹簧 / 吸附 / 错峰 / 跟随 | 运动质量的根 | 小 |
| P1 | 运镜 operator（lead/shake/float） | 镜头语言 | 中 |
| P2 | 深度动效（景深/运动拖影分层） | 高级感 | 中 |
| P2 | 逐事件音效 | 声音专业度 | 中 |

---

## 五、诚实说明：我们不追的部分

| 它有什么 | 我们不做的理由 |
|---|---|
| HTML/CSS 重建真实 UI | 我们有原生自绘 + 三维，路线不同；UI 重建那是它的强项，硬追收益低 |
| three.js / Blender GLB | 我们已有自研三维腿（且带降级），够用 |
| 多语言时间对齐 | 当前无此需求 |
| 4K60 | 能力可达，但渲染成本高，按需 |

**我们追的是「运动质量 + 排版语言 + 可验收」，那才是"不像 PPT"的本体。**
