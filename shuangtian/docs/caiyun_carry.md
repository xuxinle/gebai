# 裁云 · 跨场承接（carry）与连贯度验收

> **这份文件回答**：为什么两个画面之间"没有东西活下来"就是幻灯片，以及裁云怎么把它修好、怎么量。
> 对标 [onetake](https://github.com/feitangyuan/onetake) 的 `probe.py` carry score，但用**我们自己的口径**：
> 不靠像素猜元素身份，直接用渲染器记录的**元素轨迹真值**。

---

## 一、问题：幻灯片不是"每镜不好看"

成熟动效片判定"像 PPT"的准确形态是：**后一个画面把前一个替掉了**。
每一镜单看都没问题，合起来还是翻页——因为画面之间**没有任何东西连续**。

裁云原本的架构是：每个分镜**独立渲染**，再在边界交叉淡入。
这在结构上就属于"替换"：两个画面之间没有一个共同的物体。

**关键认知**：这不是"转场做得不够炫"。把交叉淡入换成推拉、翻页、溶解，
只要物体不连续，它依然是幻灯片——**换的是遮住断裂的手法，不是断裂本身**。

## 二、修法：承接层（`carry_out`）

在场景上声明一个**跨边界的图元**：它在 A 幕末帧与 B 幕首帧是**同一个东西**，
在这段时间里从 A 的形状变形成 B 的。

```jsonc
"carry_out": {
  "name": "承接·生长",     // 必填：验收器靠它认身份
  "into": 1,               // 交给哪一幕
  "at": 4.65,              // 变形起点（成片时间，秒）——不是幕内时间
  "dur": 0.70,             // 时长
  "from": { "x": "32%", "y": "32%", "w": "36%", "h": "36%", "radius": 16 },
  "to":   { "x": "0%", "y": "0%", "w": "100%", "h": "100%", "radius": 0 },
  "fill": "#152238", "stroke": "#4d6bfe", "stroke_width": 3,
  "text": "一镜到底", "text_color": "#9ec4ff", "text_size": 44,
  "curve": "expo_out"
}
```

**三条设计约束**（都踩过）：

| 约束 | 原因 |
|---|---|
| **必须跨过边界**（`at < 边界 < at+dur`） | 变形在边界前就结束 ⇒ 边界两侧没有共同物体 ⇒ 判 `anchored`（没动），拿半分 |
| **不许整屏不透明地盖上去** | 承接是合成**之上**的一层。整屏不透明 = 遮罩，实测把整幕文字盖没了（第 8 秒整屏蓝块） |
| **铺满阶段不能是空的** | 卡片长满后到下一幕文字出现之间，若有 0.4s 纯空卡片，观众看到的是"空屏"（实测第 160 帧） |

## 三、验收：`carry_qa.py`

```bash
# 出片时导出轨迹
caiyun --headless --script film.json --render out/film.mp4 --track-elements
# 验收（场景时长给出已知的边界）
python scripts/carry_qa.py out/trajectory.tsv --scenes 2.4,2.6,3.0,2.8,3.0,2.2 \
       --fps 30 --width 1920 --height 1080
```

判据（与 onetake 同口径，便于横向比较）：

| 判定 | 条件 | 得分 |
|---|---|---|
| `carried` | 同名元素在边界窗口内移动 ≥ 对角线 2% **或**缩放 ≥ 10% | 1 |
| `anchored` | 唯一幸存者面积 ≥ 画面 3% 但没动 | 0.5 |
| `bare` | 什么都没有幸存 | 0 |

`score = (carried + anchored/2) / 边界数`；**< 0.5 FAIL，< 0.7 WARN**。

### 我们比 onetake 更准的地方

onetake 要从 DOM / canvas 调用里**推断**元素身份（"image source + draw order"）。
我们是渲染器自己记的**图层名字与矩形**——所以同一套判据在我们这里噪声更小，
也不需要"两张元素拼一个 carry 它就看不见"那种盲区。
**代价**：脚本里必须给图层/承接起名字（没名字的身份不存在）。

### 判据本身踩过的坑（口径纪律）

**不能只取"离边界最近的那一帧"**。实测：承接图元在边界处已长得接近满屏，
"最近帧 vs 最近帧"算出的缩放变化不足 10%，被判成 `anchored`——
而它实际从 578px 长到了 1919px（轨迹一目了然，画面上也确实是"长出来的"）。
正确做法：在边界前后各取一段窗口，**取窗口内的极值**比较。

## 四、实测基准

同一条片，只差 `carry_out`：

| 版本 | carry score | 判定 | 依据 |
|---|---|---|---|
| **有承接** | **1.00** | carried | 承接卡（578 → 1919px） |
| 无承接 | 0.50 | anchored | 只剩标题A 未动 |

**0.50 这个数正是 onetake 文档警告的**：`anchored` 会让纯幻灯片拿到一半分数。
所以单看"过了 0.5 红线"不能算通过，**要看 `bare` 数量与 carried 占比**。

示例片 `assets/carry-continuity.json`（16 秒，6 幕）：

```
carry score 0.90 — 5 个边界：4 carried · 1 anchored · 0 bare
  t=  2.40  carried   via 承接·生长
  t=  5.00  carried   via 承接·生长
  t=  8.00  carried   via 承接·生长
  t= 10.80  carried   via 承接·生长
  t= 13.80  anchored  via 字标        ← 终幕静止，是节奏的一部分
```

对照 onetake 公开数据：launch 0.83（accepted）、v3 0.75（accepted）、motion-web 0.56（accepted）。

## 五、写承接的四条经验

1. **一次一个**：一个边界最多一个承接。观众注意力只有一个，两个承接等于没有承接。
2. **承接要"薄"**：它盖在画面上，整屏不透明会吃掉内容。要么用薄条/中线抽出，要么半透明。
3. **名字即身份**：`name` 是验收器认元素的唯一依据。改名字等于换元素，carry 会失效。
4. **终幕静止是合法边界**：如果最后一幕是品牌收尾，那个 `anchored` 不是缺陷——
   但要在剧本里写明，而不是让验收器替你猜。
