## 1. 为什么再加两个示例

README 的现行口径是「示例只留两个、不另起示例重复验证」。新增示例必须先回答这一条：
它们开的是 gallery / gbcode **都没碰过的职责面**，不重复单测已钉住的能力：

| 示例 | 职责面 | 主表面 | 检验什么 |
|---|---|---|---|
| `gallery` | 组件 / 设计系统（能力面） | 内置组件全集 | 组件库完整度、令牌一致性、DPI |
| `gbcode` | 文本 / 编辑器（应用面，全声明式） | `CodeEditor` | 声明式组装复杂应用、组件协同 |
| `louyue` 镂月 | **像素 / 光栅创作面**（新） | **自绘画布**——唯一以自定义 `paint_content` 为主表面的示例 | 光栅管线实战：`Canvas`/`Paint`/`BlendMode`/`Surface` 合成、逐像素操作、PNG 编解码往返、撤销栈 |
| `caiyun` 裁云 | **时间 / 动效应用面**（新） | **时间轴 + 播放**——唯一由 `UiRoot` 时间轴驱动的持续动画示例 | 帧预算与续帧协议（§11 性能目标的真实压测位）、播放/擦洗、拖拽修剪这类连续交互 |

这正是 §8.1.1 演进策略的延续：「组件先在示例里自绘验证形态，形态稳定后内置化」——
当年 `SplitView`/`CommandPalette` 从 gbcode 的示例级自绘升为框架组件，镂月的取色器、
裁云的 Timeline 是同一路径的下一批候选。

## 3. `louyue` 镂月 — 图像编辑器

### 3.1 形态与布局

Photoshop 精简骨架：内置组件搭壳 + **一个自绘画布**（`dsl::custom<T>` 逃生舱，
与 gbcode 持有 `CodeEditor` 的先例同构——高频自绘不走声明式重组）。

`WindowFrame` 外壳，自上而下：

- **标题栏**：`镂月 Lunaris — <文件名>（脏点）` + 窗控
- **菜单栏**：文件（新建 / 打开 PNG… / 导出 PNG… / 退出）· 编辑（撤销 / 重做 / 清空历史）·
  图层（新增 / 删除 / 上移 / 下移 / 合并下层）· 视图（缩放 25%~800%、棋盘格底显隐）
- **左工具栏**（窄图标列）：移动 / 画笔 / 橡皮 / 油漆桶 / 吸管 / 矩形选区 / 裁切
- **中央画布视口**：棋盘格透明底、缩放平移、光标处像素坐标实时回显
- **右侧双面板**（`SplitView` 可拖）：
  - 图层列表（`List`：可见性 eye 开关、不透明度 `Slider`、混合模式下拉——
    Multiply / Screen / Overlay / Darken / Lighten / Add / SrcOver / DstOver / Src，
    与 `raster::BlendMode` 一一对应，名字用 `to_string(BlendMode)` 同源）
  - 颜色面板（前景/背景色块、HSV 三滑杆、十六进制输入框）
- **状态栏**：坐标 (x,y) · 画布 W×H · 缩放 % · 当前工具 · 光标处颜色

### 3.2 数据模型（建议，实现轮可微调）

```
Layer  { Surface 像素缓冲; 名称; visible; opacity; BlendMode }
文档   { 画布尺寸; vector<Layer>（自底向上）; 文件路径（可空=未保存）; 脏标记 }
```

- 合成：自底向上 `Canvas::draw_canvas`，每层带自己的 opacity + blend_mode。
- 撤销：**命令式**（每笔记录受影响矩形的前后像素），不做整图快照——
  整图快照在多层大画布下内存平方级爆炸；「新建画布」这一步可用快照（一次性）。
- 画笔：高频 `MouseMove` 插值描线（上一位置→当前位置分段），大小/硬度可调，
  绘入**活动图层的离屏 Surface**，只标脏画布视口区域（`ST_PAINT_PROFILE` 下量化每帧成本）。

### 3.3 内容都是真的（承 gbcode 的「不是占位数据」标准）

| 能力 | 真实行为 |
|---|---|
| 打开 / 导出 | `st::codec::png_decode` 解码真实 PNG（`assets/` 内嵌样例 + `--open <路径>` 命令行），导出 `png_encode` 真写盘——**PNG 编解码往返第一次被真实用户路径覆盖**（此前只有单测） |
| 图层合成 | 多层 + 每层独立 BlendMode/不透明度——**九种混合模式第一次在真实界面里被人眼与像素断言同时检验** |
| 撤销 / 重做 | Ctrl+Z / Ctrl+Y / Ctrl+Shift+Z；历史面板可视化（操作名 + 步数） |
| 吸管 | 读**合成结果**像素回填前景色（像素读回路径的实战） |
| 滤镜（v1 三件） | 反相 / 灰度 / 亮度对比度——真实逐像素循环，顺带量 `src/raster/simd.cpp` 的实际收益 |
| 缩放 | Ctrl+滚轮 档位缩放（25/50/100/200/400/800），状态栏联动 |

### 3.4 控制通道钩子（**不可改名**，`tools/louyue_e2e.py` 与子代理依赖）

`#canvas`（画布）、`#layers`（图层列表）、`#history`（历史面板）、`#color-panel`、
`#status`、`#tool-brush` / `#tool-eraser` / `#tool-eyedropper`…（工具按钮）、
`#zoom-slider`。

`invoke` 动作面：`stroke x1,y1,x2,y2[,size]`（画一笔，**智能体可命令式作画后 `capture`
做像素断言**——无头闭环最有杀伤力的靶场形态）、`export <path>`、`undo` / `redo`、
`add_layer` / `remove_layer <i>`、`set_blend <i> <mode>`。

### 3.5 非目标（v1 明确不做）

文字工具、滤镜生态、选区羽化/多边形套索、CMYK/打印、RAW、色彩管理（ICC）。

## 4. `caiyun` 裁云 — 视频剪辑器

### 4.1 形态与布局

剪映 / Premiere 精简骨架。

> **诚实边界：框架没有视频解码器**。v1 的「素材」全部是程序化生成片段（走本地光栅
> 原语实时渲染）；真实视频解码是显式记入 BACKLOG 的框架缺口，**不做假占位、不冒充能播**。

- **上**：菜单栏 + 预览监视器（播放头处当前帧的合成结果）+ 时间码 `00:00:12.400` +
  传输控制（⏮ ⏵/⏸ ⏭ 循环开关）
- **左**：素材箱（生成器片段库：色板 / 渐变 / 文字 / 图形，可拖入轨道、可双击预览）
- **右**：属性检查器（选中片段的不透明度 / 变换 / 速度 / 入出点数值）
- **下（主表面）**：**时间轴**——轨道 V1/V2、圆角片段块、边缘**修剪手柄**、拖拽移动、
  播放头可拖、时间标尺、缩放滑杆、吸附开关、S 键分割（剪刀在播放头处切开片段）、
  Delete 波纹删除

### 4.2 数据模型（建议，实现轮可微调）

```
Clip     { id; track; t_in, t_out（时间轴区间，秒）; generator 类型 + 参数 }
Generator{ render(canvas, local_time, size) —— 纯函数式画一帧 }
工程     { fps=30; 时长; vector<Clip>; 播放头位置; 播放中标志 }
```

程序化片段四类（全部本地光栅原语，无解码依赖）：
**色板**（纯色 + 柔和渐变动画）、**字幕滚动**（文本渲染 + 缓动入场）、
**图形运动**（圆/矩形 + easing 轨迹）、**测试图**（自制色条/网格/时码刻度，风格自定，
不抄 SMPTE 布局）。

### 4.3 核心演示点

| 能力 | 真实行为 |
|---|---|
| 播放 | `UiRoot` 时间轴推进（正是 ui_root.hpp 里「时间轴必须由应用推进」那条教训的实战位）；播放中每帧重合成预览、脏区限定在监视器——**持续动画下的帧预算与续帧协议第一次被真实应用压测**（挂钩 §11 性能目标） |
| 擦洗 / 逐帧 | 播放头双向拖拽、←/→ 单帧步进——**确定性截图回归的完美靶子**（`invoke seek <n>` + `wait` + `capture`，同帧两次截图哈希必须一致） |
| 编辑 | 分割 / 修剪 / 移动 / 波纹删除 / 吸附——**拖拽修剪**是 SplitView 拖手柄之外的又一类连续拖拽交互，预期逼出框架级修剪交互原语 |
| 导出 | `--export-dir <dir>` 逐帧 `png_encode` 出帧序列（`frame_0001.png`… + `manifest.json` 记 fps/时长/片段表）——真实产物、无假编码器；真视频编码显式留作框架缺口 |

控制通道钩子：`#timeline`、`#monitor`、`#clips`（素材箱）、`#inspector`、
`#transport-play` / `#transport-stop`、`#timecode`。
`invoke` 动作面：`play` / `pause` / `stop` / `seek <秒>` / `split` / `select <clip_id>` /
`add_clip <generator> <track> <t_in> <t_out>`。

### 4.4 非目标（v1 明确不做）

真实视频解码（显式记缺口）、音频轨、关键帧曲线编辑（v2 候选：片段属性关键帧 + 迷你曲线
编辑器——先等 Timeline 组件形态稳定）、多机位、GPU 特效管线。

## 5. 落地顺序

**先 louyue，后 caiyun**：

- louyue 几乎全靠既有光栅能力（新组件只有取色器；画笔输入偏应用层，不动框架），
  风险低，先立「自绘画布 + 控制通道像素断言」的靶场范式；
- caiyun 的 Timeline 是框架级新组件，等范式跑通再上（内部预排序：louyue 的自绘视口
  经验直接喂给 caiyun 的时间轴自绘）。

## 7. 验收标准（完成的定义）

**louyue**：
1. e2e：打开内嵌 PNG → `invoke stroke` 画两笔（不同混合模式的两个图层）→ `export` →
   `png_decode` 回读，断言笔画像素落在预期坐标与预期混合色（±2/255）；
2. 撤销后像素与落笔前逐像素一致；重做后与撤销前一致；
3. 九种混合模式各截一张 2x 图入 `tools/` 截图基线（视觉回归参照）；
4. `st build louyue` + `st lint` + 全量测试绿。

**caiyun**：
1. 确定性：`invoke seek 1.5` → `capture`，同帧两次截图**像素哈希一致**；seek 到不同帧
   哈希不同（证明预览真的跟着播放头走，不是静帧）；
2. 修剪/分割/移动后的入出点与时长经 `get` 断言正确；波纹删除后后继片段前移量正确；
3. 导出：帧数 == ceil(时长 × fps)，抽查 3 帧与监视器 seek 同帧截图一致；
4. 播放 60s 压测（`--bench 60`）无掉帧告警、内存平稳（挂钩 §11）；
5. `st build caiyun` + `st lint` + 全量测试绿。

## 9. 风险与对策

| 风险 | 对策 |
|---|---|
| 高频 MouseMove 下画布重绘成本失控 | 只标脏画布视口；`ST_PAINT_PROFILE` 先量再优化；插值分段的段数上限护栏 |
| 播放时整帧重绘拖垮帧预算 | 脏区限定监视器；时间轴仅播放头列invalidate；§11 基线对照 |
| 声明式壳 + 高频自绘的逃生舱裂缝 | 画布/时间轴不进重组树（`custom<T>` 持引用），状态变化走显式 invalidate——与 gbcode 持 CodeEditor 同构 |
| PNG 大图解码耗时卡启动 | 解码放工作线程（`resource` 异步同款线程池），占位「加载中」态 |
| 帧序列导出撑爆磁盘 | 默认上限（如 30s/fps30 ≈ 900 帧）+ 超限确认提示；manifest 记录截断 |
