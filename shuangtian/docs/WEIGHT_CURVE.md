# 字重曲线（跨字号连续映射）

## 一句话

`resources/text_weight_curve.txt` 是一张**按物理字号查 γ / 对比度**的采样点表，
运行时可加载、可热替换——它取代了原来"低于某字号一档、高于另一档"的写法。

## 为什么不是分档

原来 `set_fitted_gamma(px, γ)` 是二档：`px <= 阈值 ? fitted : global`。
**字号是连续量**（13 × DPI，DPI 可 1.0/1.25/1.5/1.75/2.0/2.25…），
二档会在阈值处**跳变**——用户拖动字号时能看到"字突然变粗一档"，而且永远覆盖不全。

改为「采样点 + 分段线性插值」：

- 哪档偏就在哪档补一个点；
- 点与点之间线性插值，**连续无跳变**；
- 超出两端取端点值（不外推斜率，否则极字号会得到荒谬的 γ）。

## 两条控制轴的分工

| 轴 | 管什么 | 范围 |
|---|---|---|
| `gamma` | 笔画**整体实度**（单调可控，主旋钮） | [0.30, 4.00] |
| `contrast` | **满黑像素占比**（只抬中间调，对平均实度影响小） | [0, 3] |

**踩过的坑**：让两者都去拉平"平均覆盖率"，结果大字号 γ 被压到 0.30 下界仍降不下来
——因为 `contrast` 一直在给大字加分。所以表里让 `contrast` 随字号**单调降到 0**。

## 一个必须先说清的事实：霜天跨字号字重本来就基本一致

用「过渡带均值」（排除满黑区与抗锯齿尾巴后的笔画实度）实测：

| 物理px | 9 | 13 | 15 | 22 | 32 | 40 |
|---|---|---|---|---|---|---|
| 过渡带均值 | 0.416 | 0.433 | 0.437 | 0.422 | 0.421 | 0.425 |

**波动仅 5%**。

早前用「平均覆盖率」量出 **34.9% 漂移**，那个指标是**错的**：
大字号笔画宽、内部天然形成大片满黑（9px 时满黑占 0.8%，40px 时占 47.0%），
把平均值抬高了——**那是几何必然、正确的行为，不该被"纠正"**。

所以本表的定位是**可调旋钮**，不是大幅纠正。默认值接近恒等（γ≈1.0），
对现状影响极小（过渡带漂移 9.3% → 8.8%）。

## 怎么调

```bash
# 1. 看各档实测（需要探针）
python tools/dw_ab_sizecurve.py
# 2. 改 resources/text_weight_curve.txt 里对应的行
# 3. 重跑第 1 步验证
```

环境变量 `ST_TEXT_WEIGHT_CURVE` 可指向别的表（对照实验用）；
探针 `--no-curve` 显式关闭。

实测响应斜率（每 +0.1γ 时"过渡带均值"的变化，9px 最灵敏）：

| 9px | 13px | 15px | 22px | 32px |
|---|---|---|---|---|
| −0.0163 | −0.0079 | −0.0073 | −0.0057 | −0.0054 |

## 文件格式

```
# px     gamma  contrast  note
  9.0     0.95   0.30    极小字
 15.0     1.12   0.22    标准正文
 40.0     1.02   0.00
```

空行忽略、`#` 起注释、多余字段忽略；非法点（字号 ≤ 0 / 非数值）丢弃；
同字号**后来者胜**。

## 实现位置

| 文件 | 职责 |
|---|---|
| `include/st/text/weight_curve.hpp` | `WeightCurve` 类（采样点、插值、解析） |
| `src/text/weight_curve.cpp` | 实现（排序去重、夹取、二分插值） |
| `resources/text_weight_curve.txt` | 默认表（外部可编辑） |
| `src/text/text.cpp` | 生效优先级：类 γ > **字重曲线** > 字号二档 > 全局 γ |
| `tests/weight_curve_test.cpp` | 6 条回归（插值/夹取/解析/排序/端点） |
| `tools/dw_ab_probe.cpp` | `--curve=<file>` / `--no-curve` / `ST_TEXT_WEIGHT_CURVE` |

缓存：曲线内容进字形位图缓存键（`curve_bucket`），改曲线必须换位图。
