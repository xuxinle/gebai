fix(raster): spec.lighting 对脚本场景不生效（真缺陷）

用真浏览器渲 three.js 参照图做量化对照时，发现一个**贯穿前两轮修复**的缺陷：
`spec.lighting` 在脚本路径上**完全被忽略**。

## 怎么发现的

扫 `env_strength` 从 0 到 1.6 六档，六张图**逐像素相同**。这不可能——
除非传进去的 spec 没被用。

## 根因

`render_scene` 里：

```cpp
scene.set_lighting(script_scene->lighting);   // ← 脚本抽出的原始值
```

而 `spec.lighting`（含所有显式设置）被丢掉了。后果：

| 设置 | 看起来应该生效 | 实际 |
|---|---|---|
| `lighting.env_strength` | 金属有环境反射 | **无效**（仍为 0） |
| `lighting.tone_map` | bpy 场景用 AgX | **无效**（仍为 ACES） |
| `lighting.ambient/diffuse` | 能调 | **无效** |

三个都**不报错**，只是"照原样渲"——所以前两轮改的 `tone_map` 与
`env_strength` 在脚本场景里**从未真正生效过**。

修法：改用 `spec.lighting`（它在 `scene_spec_from_bpy` / `scene_spec_from_three`
里已从脚本值初始化，不丢信息）。

## 真浏览器参照图（新的量化基础设施）

用 playwright + 无头 Chromium（WebGL 2.0 已验可用）跑**真 three.js r160**，
场景与 `bpy_watch.py` 逐参数同构（同齿形算法、同材质、同光照、同相机）。

首次量化对照（1100×800）：

| 指标 | 本框架 | three.js | 差异 |
|---|---|---|---|
| 均值 | 95.6 | 76.9 | +18.7（偏亮） |
| 暗部（<64） | **0.0%** | 9.8% | 无阴影层次 |
| 中间调 | **99.9%** | 89.3% | 画面平 |
| 最亮 | 210 | 255 | 高光不够 |
| 直方图重叠 | **0.088** | | 分布几乎不重叠 |

## env_strength 标定

修好上面那个缺陷后，六档真的各不相同了，扫出最佳值：

| env_strength | 均值 | 重叠度 |
|---|---|---|
| 0.00 | 95.9 | 0.088 |
| 0.30 | 85.7 | 0.109 |
| **0.60** | 90.5 | **0.111** |
| 0.90 | 94.1 | 0.097 |
| 1.20 | 97.0 | 0.095 |
| 1.60 | 100.0 | 0.090 |

0.6 是实测最优（不是拍脑袋）。但重叠度只有 0.111 说明**主要差异不在这一项**。

## 暗部为 0 的根因（诊断，未改）

逐档扫 ambient/diffuse/env：

| 配置 | 均值 | 暗部% |
|---|---|---|
| 现状（amb .35 diff 1.65 env .6） | 89.9 | **0.0** |
| ambient=0 | 88.7 | 0.0 |
| ambient=0 env=0 | 89.6 | 0.0 |
| **diff=0.8 其余低** | 81.0 | **5.1** |

只有压低 `diffuse`（来自脚本的灯 `energy=2600`）才出现暗部。说明**漫反射强度
是亮度下界的主导**，而三路的光照单位本就不同（Blender W/m² vs three 无量纲）。

这属于**光照积分层**的差异，计划里已列为「必然有差」——不是能用参数调平的。
诚实记录，不假装对齐。
