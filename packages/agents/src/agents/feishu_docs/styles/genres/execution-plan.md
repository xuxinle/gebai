# 体裁：执行计划（Execution Plan）

**读者任务**：把已批准的方向转成可协同推进的交付、依赖、里程碑与验收。

**骨架**：已批准结果与成功标准 → 范围与非范围 → 交付物 / 工作流 → 依赖与关键路径 → 带退出条件的里程碑 → owner / 接口 / 资源 → 风险触发与备选 → 治理、变更与验收。

**硬约束**
- 区分已确认承诺、估算、假设与待定项；未批准的方向不得写成承诺。
- 按**交付物**而非部门名称拆工作包；每个关键工作包写 owner、输入输出、依赖、完成定义与验收方。
- 日期必须由依赖、产能与必要审批/制作时间推导；无法推导时用相对时间、区间或具体占位，不补造精确排期。
- 风险写预警信号、影响、预防/响应动作、决策 owner 与备选路径；备选要说明何时切换、切换后的终态。
- 治理只保留会产生判断的节奏：接口、升级条件、决策权、范围与基线变更、重新验收。

**常见错误**：任务清单冒充计划；活动无交付物与完成定义；里程碑只是日期；排期不服从依赖与产能；所有事项同优先级；接口或验收方缺失；风险无预警信号与动作；变更后不更新基线。
