# 体裁：PRD / 产品需求

**读者任务**：产品、设计、研发、测试就「用户问题、范围、可观察行为、完成标准」形成共识。

**骨架**：用户问题与证据 → 目标与可观测结果 → 范围 / 非目标 → 关键场景 → 行为需求与验收 → 异常与边界 → 质量约束 → 依赖与开放问题。

**硬约束**
- 明确目标用户、任务情境、问题及研究/行为/支持证据；内部偏好和预设功能不冒充用户需要。
- 需求写成 actor + 触发/前置 + 可观察结果 + 失败与边界；术语与状态全文一致。
- 目标连接可观测结果，指标标口径、来源与时间窗；未知阈值写 `[待某角色某时点确认]` 并给责任人，不编数字。
- 先定范围、非目标、优先级、依赖、假设与开放问题，防止 scope creep；大而不可测的需求拆到可验收粒度。

**常见错误**：功能清单没有用户问题；非目标缺失；需求暗藏实现方案；验收不可测（「体验更好/性能更高」）；正常路径无异常；机械填合规/无障碍模板。
